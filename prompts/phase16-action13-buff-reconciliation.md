## 3. 本命: 超化（capExtend）と段数集約の決着

### 3.1 実測（S2 L3・全 168 ビート。`サンプル2/measured_data_v3.json`）

| 行 | 値 | 出現窓 |
|---|---:|---|
| `クリティカル係数上昇` | 8 | b2–44 / b51–94 / b101–144 / b151–167 |
| `クリティカル係数上昇超化` | **10（常に 10）** | **b14–43 / b88–127 / b148–167** |

- 基本行の窓は 45 ビート（P `sk-chs-05-fest-00-2` = 8段 [45b]・CT 50 → b1/b50/b100/b150 発動）と一致。
- **超化行は基本行と寿命が独立**: 基本行が消えている b95–100・b148–150 でも超化行は残る。
  → engine の「**最長インスタンスに合算**」(`src/timeline/buffs.ts` L338-365・`src/timeline/engine.ts` L1549-1552)
  とは別機構である可能性が高い。
- 超化行の値は 3 窓すべて **10**（5 や 15 にはならない）。5段×2 インスタンス説・上限拡張量説・
  クランプ説のどれでも説明できるので、**ここは §3.2 の検定で決める**。

### 3.2 engine 側の現状（要確認・重要）

- `vocal_up_extreme` / `dance_up_extreme` / `visual_up_extreme` は**独立キー**として実装済み
  （`src/timeline/buffs.ts` L134-142・L236-239、1段 50‰ = `STATUS_UP_EXTREME_PER_STAGE_PERMIL`
  `src/timeline/constants.ts` L66、上限 30 = `LIMIT_RELEASE_STAGE_CAP` L108）。
- **`critical_coeff_up_extreme` は存在しない**（`grep -n "_extreme" src` で確認済み。critical 系は
  `critical_coeff_up` と `critical_coeff_limit` だけ）。
  → マスタが超化を `capExtend: true` で表す `sk-chs-05-fest-00-1`（A・critical_coeff_up 5段 [41b]）は
  基本キー側に流れ、A12 の実測ログでは **`critical_coeff_up` が 8 → 13 に増えていた**（= +5 合算）。
  実機は「超化」という**別の行**として表示している。
- S3 には `ビジュアル上昇超化` と **`ビジュアル上昇上限開放`** の行がある（＝別ファミリで同じ機構が観測できる）。
  `NAME_TO_BUFF_KEY` に `*上昇超化` はあるが、**`クリティカル係数上昇超化` と `*上限開放` は入っていない**
  → まず表を補う（`tools/analyze_beat_score_models.ts` L1386〜 と `tools/audit_s1_b136_step11.ts` L54〜 の 2 箇所）。

### 3.3 検定する 3 仮説

| # | 仮説 | 予測（S2 L3 b102–167） |
|---|---|---|
| H1 | 超化は独立キーで**加算**（表示 10 をそのまま足す） | 8+10 = 18段 → 要求 12.33 と**合わない**（棄却見込み） |
| H2 | 超化は**上限拡張のみ**（係数は基本 8 のまま） | 8段 → 要求 12.33 と合わない（棄却見込み） |
| H3 | 超化は基本に対する **+5段階分**（マスタ注記どおり）で、**寿命だけが独立** | 8+5 = 13段 → 要求 12.33 ± 0.53 と**整合**（最有力） |

A12 の pop 逆算（`phase16_action12_critprobe.ts`・非クリ層で正規化した要求段数）:
**b2–14 = 8.45**（sim 8 ✓）／**b15–93 = 12.76**（sim 13 ✓）／b95–100 = ~12（sim 0 ✗）／
**b102–167 = 12.33 ± 0.53**（sim 8 ✗）。
→ **値は「基本 + 5」で説明でき、寿命だけが engine と違う**、が最有力。
（超化行が b88 から出ているのに b15–93 の要求が 12.76 = 13 なのは、**b15–87 でも +5 が効いていた**ことを意味する。
表示行が b88 以前に出ていないのは抽出漏れの可能性がある＝ §7 の罠 1 を参照。）

## 7. 既知の罠（先に潰すこと）

1. **S2 の `effects` は抽出漏れがある疑い**。超化行が b88 以前に出ない一方、pop は b15–87 でも +5 を要求する。
   同じく **S2 の v3 には `lanes` キー `2` が 1 つも無い**（`1/3/4/5` のみ）。
   行の「無い」を「バフが無い」と読む前に、`no_frame`/遮蔽や抽出スクリプト（`extract_all_s2_buffs.py`）の
   走査範囲を確認する。
2. **`deck.json` の `lane` フィールドと実レーンの対応が怪しい**。S2 は `card-chs-05-fest-00`（`lane: 4`）の
   スキル（critical_coeff_up 8段のP・capExtend のA）が **L3 の表示行と pop の両方**に一致し、
   そのレーンだけ総スコア 49.8M（他は 4〜12M）と突出する。**`lane` を鵜呑みにせず、
   `results.scores_by_lane` と突き合わせてから**レーン別解析をすること。
3. `/クリティカル係数/` の正規表現は **`クリティカル係数上昇超化` にも一致**する。
   行を引くときは `name === "..."` の完全一致で（A12 はこれで一度混同した）。
4. `src/` の超化は 2 系統ある: (a) 独立キー `*_up_extreme`（vocal/dance/visual）と
   (b) `capExtend` による基本キーの上限拡張（L338-365）。**critical は (b) にフォールバックしている**。
5. A12 の pop 逆算は beat ノートの flat 加算が 0 であることを前提にしている
   （`engine.ts` は A/SP にだけ `aScoreFlat` を足す）。A/SP セルには同じ式を使わないこと。
