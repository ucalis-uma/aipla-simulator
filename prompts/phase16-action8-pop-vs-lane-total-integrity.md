# Phase 16 アクション8: S3 L5 の「pop 合計 > レーン合計」疑いのデータ健全性監査（読み取り専用・並行可）

作成: 2026-10-01 ／ 対象: S3 L5（sim/実測 1.3737）の実測側の健全性 ／ **engine・src は触らない**
依存: なし（アクション6/7 と**並行実行してよい**。`src/` を編集しないため）

## 1. 出発点（`phase16_action5_lane_gap_out.txt` の表から導いた疑い）

S3 legacy モードのレーン別表（sim / 実測 / sim比 / pop 読込セル数 / Σ(pop−sim)）:

| レーン | sim | 実測 | sim/実測 | pop 読込 | Σ(pop−sim) |
|---|---|---|---|---|---|
| L1 | 5,701,276 | 5,931,931 | 0.9611 | 147 | +153,679 |
| L2 | 4,045,306 | 9,859,761 | 0.4103 | 148 | +5,745,047 |
| L3 | 15,641,146 | 18,344,645 | 0.8526 | 150 | +198,742 |
| L4 | 35,305,020 | 35,714,608 | 0.9885 | 147 | +285,545 |
| **L5** | **13,133,281** | **9,560,444** | **1.3737** | 141 | **−113,820** |

- **L5 だけが構造上おかしい**: pop が読めるセルでは sim と pop がほぼ同額（Σ(pop−sim) = −113,820）なのに、
  **レーン合計は sim の 72.8%**。読込セルの pop だけでレーン合計を数百万レベルで超過している計算になる
  → 「**pop の over-sum（表示ラグの二重計上）**」か「**レーン帰属の誤り**」か「**measured のレーン合計のほうが取りこぼしている**」のいずれか
- 検査が機能することの示標（対照）: **S2 L3** は Σpop ≈ 85,427,932 − 35,737,809 ≈ **49.69M** でレーン合計 **49,841,012** と整合する
- S3 L5 の「sim が +37% 大きい」という**乖離そのものが pop 読込セル上には存在しない**（読込セルは一致）。
  つまりこの +37% は **pop が読めないセルにあるのではなく、pop 系列とレーン合計の口径差**である可能性が高い

## 2. タスク

### タスク1 口径一致マトリクス（本命・必須）
S1・S2・S3 × 全 5 レーンで `Σpop(読込セル)` と `実測レーン合計`（`results.scores_by_lane` / `results.lane_scores`）を直接計算し、
`Σpop / レーン合計` の表を作る。**> 1.00 になるセルを全件列挙**する（S3 L5 が該当する疑い）。
併せて「pop 読込セル数」「読込セルのビート被覆率」「末尾/先頭の取りこぼし」を同じ行に載せる。
出力: `phase16_action8_pop_vs_lane_total.mjs`（または `.ts`）+ `_out.txt`。**数値は必ず計算して出す**（表からの推論で確定させない）。
### タスク2 over-sum（二重計上）の検出
同一レーンで **±1 ビート以内に同一 text の pop が並ぶ**事例を全件数える（表示ラグの二重計上は S1 遡及で b1 帰属ラグとして既知）。
二重計上を除去して `Σpop ≤ レーン合計` になるか、なるなら除去件数は何件かを報告。
### タスク3 帰属の再点検
`lane_pops_backfill.json` の `lane` / `position` と `POSITION_TO_LANE`（`src/timeline/constants.ts` = `[3,2,4,1,5]`）の対応を全セルで検証。
A/SP ノートのビートでは「その譜面のノート位置が払う」はずなので、**A/SP ビートでの pop レーンとノート位置の一致率**をサンプル別に出す
（アクション5 では S3 の 3 セル・S2 の 2 セルが全て一致していた。一致率が低い層があればそこが帰属誤りの候補）。
### タスク4 measured 側のレーン合計の信頼性
`scores_by_lane` の 5 レーン合計が `total_score` と一致するか（S1 116,537,513 / S2 77,732,383 / S3 79,411,389）。
不一致なら**レーン合計のほうが容疑者**。クロップ/読み取りの取りこぼし疑いは `fan.png` 等の原画像があれば**追記形式で**再確認する。
### タスク5 結論の記録
`research/23_beat_score_analysis/phase16_action8_report.md` に「S3 L5 の +37% をどう扱うか」を書く:
**(i) 実測側のデータ問題（→ L5 の乖離はシミュレータの欠陥として扱わない／次サンプルまで保留）**
**(ii) pop 系列の過大計上（→ 検証用の pop 系列を `lane_pops_backfill2.json` 等に追記形式で作り直す）**
**(iii) sim 側の欠陥（→ アクション6/7 とは別枠の修正事項として起票）**
実装ログ末尾にも節を追記する。
