## 1. 背景とアクション1の成果

Phase 16 アクション1（`tools/analyze_beat_score_models.ts`）により、以下の事実が確定した：
1. **λ = 1/20（やる気士 docs 式）は棄却**: 白ノーツ比率が全サンプルで現行比 0.875 倍（−12.5%）となり全滅。**現行の λ = 8/140（約 5.714%）が唯一生存**。
2. **フォト `beat_score` は現行 `max` を維持**: 判別可能セルが極少で、S2 の sum 優位は系統ズレの吸収による偽シグナルと判明。
3. **S3 confirmed ギャップ（−8.62%）の 93% はクリティカルプレミアム（+1,253万点）の非発動**: 通常ビートの差分は総スコアのわずか **0.21%**（−16.7万点）。通常ビートの式がギャップを作っているという仮説は棄却された。
4. **真の未解決課題（アクション2 の対象）が浮上**:
   - **S2 の一律 −7.5% オフセット**: 全レーン・全32純白ビートで sim が実測より約 7.5% 低い（pop/sim 平均 1.085、σ=0.013 と極めて均一）。
   - **S3 の L2 / L4 突出**: L1/L3/L5 は 0.95〜0.97 で揃っているのに、L2（1.0945）と L4（1.0916）だけ約 +9% 高い（L2 には beat_score 写真がなくフォト集計では説明不能）。
   - **S3 実測のみ発動 8 ビート**: スキル発動ビート差分（−66.3万点、残差の 71.6%）の主因候補。

### タスク 2: S2 の「一律 −7.5% 低い（実測比 1.085）」要因の究明
全レーン・全ビートで一様に実測が高く出ている（σ=0.013 の平行移動）原因を特定する。以下の候補因子を順に点検する：
1. **ファン数・来場者ボーナス**: `Quest.json` / `QuestAudienceAdvantage.json` と S2 の audience 設定値（66,031人）の計算（`fan_bonus`）が実機画面（`fan.png` 等）と一致しているか。
2. **ステージ補正 / 属性係数**: STAGE680 の `stageFactorPermil` や属性重み（600/250/150）の解釈。
3. **ライブボーナス（live_bonus）**: S2 撮影時にステージ固有のライブボーナスが存在したか（`live_bonus.png` の有無と反映状況）。
4. **デッキステータス**: `examples/sample2.json` / `deck.json` のステータスが実機スクショ（カードLv、エール、フォト等のステータス）と一致しているか。

### タスク 3: S3 の「L2 / L4 だけ +9% 高い」要因の究明
1. L2（成宮すず）と L4（一ノ瀬怜）の実機ステータスとシミュレータ内部ステータスを突合する。
2. ステージ属性補正（STAGE045 は Visual 特化 1200‰・他属性 500/300‰）がレーンまたはキャラクターにどう適用されているかを点検する。
3. 未反映の自己バフ、パッシブスキル、エール効果がないかを確認する。

### タスク 4: S3「実測のみ発動 8 ビート」の特定と解明
1. `phase16_action1_data.json` で記録された「sim のみ 0 件 / 実測のみ 8 件」の該当ビート番号とレーン番号を特定する。
2. その 8 ビートで実機で発動しているスキル（Aスキル、Pスキル、フォト等）を特定し、なぜシミュレータ側で不発判定（CT中、スタミナ不足、条件不成立等）になったのかの原因を突き止める。
3. この発動漏れを解消した場合、スキル系差分 −662,768 点がどれだけ縮小するかを試算する。
