## 4. リプレイ画面の構造（1080×1920・座標は概算、必ず自分で再計測してから一括処理へ）

1 枚（例: `lane3\beat_060.PNG`）に以下が入る:

- **左上**: 累積スコア `18,780,790/71,000`（= 全レーン合計の累積 / 目標スコア）
- **右上**: `COMBO 4 RANK S+27`（COMBO はヒット済みノート数。この曲はビート数 ≠ コンボ数に注意）
- **注目レーンカード**（上段・y≈130-460）: アイドル名・現在ステータス値（バフ込みの表示値。
  例: L3 が 366355）・スタミナ `6751/6933`（現在/最大）
- **スコアポップ**（レーンカード右上・y≈160-200）: このビートのこのレーンの獲得スコア。
  **黄色 = CRITICAL / 白 = 通常**（`research/09` の色分類を参照。ただし +38.6K のように
  省略表示なので、正確な値は累積スコアの差分で求める）
- **現在の効果ボックス**（y≈480-710・右に縦書きラベル「現在の効果」）:
  フォーカス中レーンの発動中バフ（`10段階 クリティカル率上昇` 等・段数付き）。
  **約 5 行でクリップされる**（最終行が半分に切れていたら、さらに下のバフが隠れている可能性）。
  隠れ分は下段カードのバフアイコンで裏取りし、それでも不明なら【Unknown】
- **ノート種別ヘッダー行**（y≈745-800・5 列）: 各レーンのこのビートのノート種別
  （`多`=複数ノート / `SP`=SPノート / 空白=なし）+ 属性（ボーカル/ダンス/ビジュアル）。
  **チャートのノート配置がそのまま読める**ので全ビート分記録する
- **BEAT 数字**（右端・`capture_lane_generic.py` の OCR ROI `[820:885, 900:1070]`・閾値 210）:
  現在のビート番号。ファイル名の beat_NNN と一致することを必ず検証する
- **下段 5 レーンのカード**（y≈1460-1745）: 全レーンのバフアイコン + 数字バッジ
  （効果残りビート数）+ 下の**青ドット = そのレーンのスキル発動回数**（要検証。
  最終ビートのドット数が result_charactor の ×N と一致するかで意味を確定させる）
- **左下 `Pスキル` チェック / 右下 `終了する`**: UI 要素（データではない）

T5 の座標（research/08・09）は **1668×2420（iPhone 撮影）** 基準で、本サンプルは
1080×1920 かつアスペクト比も異なるため、**座標の持ち回しは不可**。読取技法
（黄帯を分離する閾値、max 値照合の自己検証、白/黄ポップ分類、前後フレーム差分での異常検知）だけを継承し、
座標は `order_01.PNG`・`lane3\beat_000/060/176.PNG` 等で再計測して座標表を作ってから一括処理に進むこと。

   各レーンのスキル構成（A/P/SP の有無）を `lane{N}_charactor.PNG` と timeline で確認し、
   SP ノート到来時に未所持なら `FAIL スキル未習得` として記録
