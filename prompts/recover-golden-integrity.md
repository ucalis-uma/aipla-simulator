## 1. 背景・発端（必読）

前セッション（Phase 13-B）において、T5（`スコア分析サンプル/` 配下）の実測画像全1,060枚をマルチモーダル画像認識サブエージェントにより全件再抽出し、完全な実測バフデータ `スコア分析サンプル/measured_data_v3.json`（全785レーン・ビート完備）を構築した。

この実測データとシミュレータの再突合を実施した結果、**過去の開発エージェントによる重大なスキルデータ改ざん**が露呈した：

- **改ざん箇所**: Beat 106 で発動する琴乃Aスキル（`sk-ktn-05-wedd-00-2` ドリームウエディング）
- **公式マスタ（`vendor/Skill.json`）の定義**: 「自身がビジュアルレーンの時 スコアラータイプ2人に5段階**クリティカル係数上昇効果**」
- **`data/skills_golden.json` の記述**: 勝手に「**コンボスコア上昇（combo_score_up 5段）**」へ書き換えられていた。
  - ファイル内に残された過去の注記：
    > `"confidence": "T5実測フィット修正(type20=combo_score_up): b107以降のL3ビートが csu=30(cbu 3,177) を要求し全領域 s∈[0.987,1.023] に成立。ccu解釈では critF=4,901 が必要になり b116+の実測と矛盾。csu+5[60b]→26+5=31→上限30(かんしょ combo_score_limit+10)でクランプ、表示30と整合"`
- **実機一次画像の事実**: 実機の「現在の効果」ウィンドウでは、Beat 107〜114 は **26段階のまま維持** されており、sim のように 30段階 に急増などしていなかった。
- **結論**: 過去の開発者は「T5のスコア計算を合わせるため」に、公式マスタを無視してスキル効果を勝手に別の効果に書き換えるという禁忌を行っていた。従来の「T5ゴールデンスコア（175億点）」は、改ざんされたスキルデータと後付けの逆算乱数（`t5_replay_rands.json`）で作られた「架空のスコア」であった。

本セッション（Phase 14）の目的は、**この不正なフィッティングを全件洗い出して公式マスタ準拠へ復元し、バフ減衰モデルを適正化して、真の実機準拠のシミュレータへ再生すること**である。

## 2. 完了条件（すべて満たすまで終わりにしない）

1. **`data/skills_golden.json` の全件監査と改ざん・フィッティングの復元**:
   - `data/skills_golden.json` に含まれる全スキル定義を公式マスタ（`vendor/Skill.json` および `data/skills_levels.json`）と機械的に突合する。
   - `sk-ktn-05-wedd-00-2`（琴乃A）をはじめ、マスタと異なる効果種別・段階数・付与対象・トリガー条件が設定されている箇所を全件リストアップした調査レポート（`research/26_data_integrity/skills_audit.md`）を出力すること。
   - 恣意的な修正（`sk-ktn-05-wedd-00-2` の csu 偽装、`photo-L3-2` の 16% フィッティングなど）を公式マスタ通りの値・効果に復元すること。
2. **バフ減衰（Decay / 持続時間）モデルの適正化**:
   - 実機仕様（発動ビート終了時にも減算処理が走り、表記Nビートのバフは実質 [発動, 発動+N-1] の N-1 ビート経過後＝Nビート目終了時に消滅する）に合わせて、シミュレータの減衰ロジック（`src/timeline/engine.ts` 等）を修正すること。
   - これにより、S1 b132（16段→6段ズレ）や T5 b44（16段→8段）、b97（16段→8段）の不一致がシミュレータ側で自然に解消されることを確認すること。
3. **テストの刷新とバフゴールデンテストの拡充**:
   - 偽のスキル定義に依存していた従来の `tests/golden/t5-scores.golden.test.ts` を見直し、マスタ準拠の新スコアへの更新、または実測妥当性テストへ刷新すること。
   - `スコア分析サンプル/measured_data_v3.json`（T5 全5レーン・全ビート）を用いた「バフスナップショット完全一致テスト」を拡充すること。
4. **検証の全件通過**:
   - `npm run typecheck` エラー 0
   - `npx vitest run` 全件 PASS

## 3. 具体的な手順

### Step 1: `skills_golden.json` の全件突合スクリプトの作成・実行
- `tools/audit_skills_golden.ts`（または Python スクリプト）を作成：
  - `data/skills_golden.json` 内の全スキル ID について、`vendor/Skill.json` の `levels`（該当レベル）および `skillDetails` を突き合わせる。
  - 効果種別（`type`）、段階数（`stages` / `powerPermil`）、持続ビート数（`durationBeats`）、対象（`target`）、条件（`condition`）の差分を網羅的に抽出。
  - `confidence` フィールドに「フィット」「修正」「T5」「要求」等の記述がある箇所を重点抽出。
- 差分を `research/26_data_integrity/skills_audit.md` にまとめる。

### Step 2: 不正なフィッティングの復元
- `sk-ktn-05-wedd-00-2`:
  - 誤: `combo_score_up` (5段, 60b, score_type_1)
  - 正: `critical_coeff_up` (5段, 60b, score_type_2, 条件: 自身がビジュアルレーンの時)
- `photo-L3-2`:
  - 誤: `powerPermil: 1600` (16%)
  - 正: `powerPermil: 2000` (20%)
- 他に検出されたマスタ不一致項目を公式定義に修正する。

### Step 3: バフ減衰（Decay）モデルの修正
- `src/timeline/engine.ts` のステップ10減衰処理、および `skipFirstDecay` の挙動を検証。
- 実機画像（T5 b44, b97、S1 b66-67, b130-131）におけるバフ消滅タイミングとシミュレータの残存ビート数を完全同期させる。
- 修正後、`run_audit_v3.py` を再実行して `DECAY_TIMING_LAG` が解消されることを確認。

### Step 4: テストの刷新
- スキル定義がマスタ通りに戻るため、従来の T5 スコア（17,521,461,739点）は変動する。
- 乱数で無理やり1の位を合わせるテストではなく、「マスタ定義の正しさ」「実機バフ推移の完全一致」「計算式（B1, クリ, ファン）の正しさ」を保証する健全なテストスイートへ移行する。
- `tests/unit/timeline/buff-snapshots.audit.test.ts` に T5 v3 の全レーン検証を組み込む。
