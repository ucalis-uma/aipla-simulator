## 1. 作業

### T1 act 単位コスト表の構築（読み取り専用・新規スクリプト 1 本）

`research/23_beat_score_analysis/phase16_action9_act_cost.ts` を新設し、**S1 の前→後ペア**と **S3 の終了点読み**
から「1 発動あたりの実測コスト」を抽出して **sim が同じ (lane, beat) で払った額**と横に並べる。

- S1: 同一 (lane, beat) の `stamina_phase="発動前"` と `"発動後"` を対にして `cost = before − after`。
  `stamina_display` は "現在/最大" なので **スラッシュ前で割る**。ペアが揃わない act（前後どちらかだけ）は
  `null` + 理由列を付ける。**S1 の 34 件を必ず全件**出す。
- S3: act は**終了点**読み。同一 (lane, beat) に複数 act がある場合は**時系列順の差分**で 1 件コストに分解する。
  直前 act（またはビート開始値）を基準にできないものは `null` + 理由。
- sim 側は**既存ハーネス `phase16_action5_lane_gap.ts` / `phase16_action6_stamina_ledger.ts` をコピーして拡張**
  （`buildSimulateInput({ data, audience, laneFans, ... })` → `simulateTimeline`。engine の export は `simulateTimeline`。
  **自前で `deck/stage/chart` を組まないこと** ← 前のセッションがここで起動失敗した）。
  sim 側の「どの act をいつ、いくらで発動したか」がビート分解能で出ていないなら、**エンジン触らずに**
  出力拡張（events に act 単位で載せる / 解析用の別出力）から始めること。
- 出力表の列（全 act 1 行）: `sample / lane / beat / type / skill_name / skill_lv / 実測cost / sim_cost / delta /
  delta% / simの発動有無 / 実測の発動有無 / sim発動ID / 実測スキル名一致(0/1)`

**集計で必ず出す 4 数字**: ①type 別の一致率と delta の中央値 ②delta ≠ 0 の act が**フォトだけ**か ③実測 cost の
同一スキル名・同一 Lv 内ぶれ（最大/最小比） ④sim cost が「stock 値」か「stock×3」か、サンプル別の切り替わり。

### T2 フォトの三角照合（**本アクションの山場**）

`deck.json のマイフォト登録 ⇔ 発動バナーで読めた実コスト ⇔ sim が発動したフォト` の 3 角を
**S1・S2・S3 の全レーン**で突き合わせ、不一致を次の**3 分類**する:

| 分類 | 意味 | 訂正場所 |
|---|---|---|
| **(α) 入力データ誤り** | `deck.json` の `photos` が実際に編成されていたフォトと違う（撮影時の転記誤り） | サンプル側は**変更せず**、`data/` 側のオーバーライド＋ユーザー提示 |
| **(β) 選択ロジック誤り** | 登録は正しいが sim が違う枠のフォトを発動している（順序・CT・`usedThisBeat` 予算） | `src/timeline/engine.ts`（T5 で承認ゲート） |
| **(γ) コスト式の誤り** | 正しいフォトに対して sim の 1 件コストが違う（×3 の適用・二重換算・Lv 反映） | 同上（コスト算出部） |

- 判定には **Info Pride マスタ**を使う: `https://idoly-backend.outv.im/api/Card?id=<カードID>` でカード→スキル ID、
  `https://idoly-backend.outv.im/api/Skill?ids=<スキルID>` の `levels[].description` で**レベル別スタミナ消費**。
  **スクショの読み取りで語らないこと**（AGENTS.md の参照規則）。ローカルに寄せるなら `tools/importers/` の既存形に従い、
  生マスタを `data/` 直下に置かないこと。
- 「**同一スキルなのに ±6%**」は次の 4 候補を**すべて機械的に潰す**:
  ① `effect_lines` / `effects_now` に**スタミナ消費削減**系の効果があるビートだけ安いか（S3 55 件で検証可能）
  ②Lv バッジの誤読（同じ名前でも別 Lv の混在） ③OCR 誤読（`order_*.PNG` を直接見て確認、**元画像は変更しない**）
  ④消費が現在値または最大スタミナに比例する式（`cost / max`、`cost / 現在値` を分布で出す）
  → どれか 1 つに**数値で**寄せること。寄せられなければ【Unknown】で残す。

### T3 成否逆転の両方向が T2 の説明で再現できるか（**engine を触る前の関門**）

T2 の分類が確定したら、**engine を編集する前に**「この訂正で b70×L5 は FAIL 側になり、
b4×L2 / b34×L2 / b169×L3 は成功側になるか」を**予測として文章で先に書く**。その上で:
1. T2 の分類を**解析側のオーバーライド適用で模擬**する（engine を編集せず、フォト参照だけ差し替えた別実行）。
2. 4 セルの成否が反転するなら本修正へ（T5）。反転しないなら**分類が wrong** なので T2 に戻る（ここで書き足さない）。
3. 反転したが**別のレーンが壊れる**なら、その崩しを全レーンの末尾スタミナ表と pop 整合で特定してから報告する。

## 3. 判定基準・落とし穴

- **A6 の結論をなぞらないこと**。「残余はフォト局在」は**起点**であって結論ではない。**同じ話の繰り返しで終えるのは失敗**。
  少なくとも「±6% の成因」「α/β/γ の裁定」「4 セルの反転再現」の 3 つは**新しい数値**で埋めること。
- **「実測が読めないから不明」は 2 回まで**。S1 34 件＋S3 55 件は未消費の材料なので、まず使い切ること。
- `timeline[].stamina.current_stamina` は**発動途中の値**（A6 §1）。終了点同士で比べる限り是对的だが、
  act 読みと突き合わせない逐ビート比較を**台帳テストの根拠にしない**こと。
- **全局乗数（STAM_INIT / STAM_COST_MUL_PERMIL / STAM_REC_MUL_PERMIL）を触るのは禁止**（A6 で棄済み:
  S1 L1 176/176 一致と両立しない）。
- pop に定数を合わせに行く改ざん禁止。実測サンプル（`../aipura_nox/サンプル*/`）は**読み取り専用**
  （`deck.json` を直したい場合は**変更せず**、`data/` 側のオーバーライド＋このレポートに「要ユーザー判断」として記載）。
- 旧プロンプト A7（S2 b90 の SP 上振れ）とは**同じ engine.ts を触るため同時実行しない**。A9 が先。
