## 1. 背景と確定成果（出発点）

Phase 16 アクション3b（`research/23_beat_score_analysis/phase16_action3b_fan_full_house.md`）により、ファンボーナスの真の仕様が **5サンプル 25/25 完全一致** で確定した：

1. **ファンボーナスの真の規則（満員一律・空席レーン別）**:
   - **来場合計 ≥ 会場キャパ（満員）**: 全レーンが **`f(capacity/5)`（=「※最大」値）の一律適用** になる（S1, S3, S4 は 100% 満員で全レーン同一）。
   - **来場合計 < 会場キャパ（空席あり）**: 各レーンの個別来場数に基づく表引き `f(lane_fans[i])` が適用される（S2, S5 の全10レーンが表引きと 0.1pp 単位で完全一致）。
   - 素朴な「全会場レーン別表引き」は **13/25 不一致**、この「満員一律ルール」は **0/25 不一致（100%合致）**。
2. **エンジン実装への決定的な教訓**:
   - 現行エンジンの「単一 `audience`（レーン平均）を全レーンへ適用」は、**満員会場（S1, S3, S4）では実機と完全に一致している**。
   - 満員ガードなしで素朴にレーン別表引きを実装すると、**S3 L5 が係数 −2.4%、L3 が +0.9% という大きな後退（改悪）** を招く。
   - したがって、**`lane_fans[]` の実装には「満員ガード（来場合計 ≥ キャパなら一律 f(cap/5)）」が必須**である。
   - **S3 のレーン別スコア乖離（L2/L4突出など）は fan が原因ではない**ことが完全に確定（fan は全レーン一律 +37.5% のため）。
3. **環境整備**:
   - `tools/probe_beats.ts` を移設し、`npm run typecheck` は **0 エラー（完全グリーン）** に復帰済み。

## 2. タスク一覧

### タスク 1: 満員ガード付きレーン別ファンボーナス（fan_per_lane）の安全実装
* `src/sim/build.ts`（および関連型定義）に、以下のロジックでレーン別ファンボーナスを組み込む：
  ```ts
  const isFullHouse = declaredTotalAudience >= maxCapacity;
  const fanBonusPermil = isFullHouse
    ? lookupFanBonus(Math.floor(maxCapacity / 5))
    : lookupFanBonus(laneAudience[laneIndex]);
  ```
* `stage.lane_fans[]` 未指定時は従来の単一 audience からの導出を完全互換で fallback 維持する。
* 空席会場（S2: 充足率94.3%、S5: 充足率77.0%）でレーン別相対精度が向上すること（S2で最大±1.6%、S5で最大±2.0%改善）、および満員の S1/S3/S4 で既存スコアが 1 点も劣化しないことを検証する。

### タスク 2: トレース `fan` 欄と表引きの 0.6〜1.9% 不一致の解明
* 解析トレース上の `fan` 欄が、マスタ表引き値よりわずかに低く出る現象（S1 1001/1002、S3 1361/1375、T5 1590/1620、S2 1554/1564）の原因を特定する。
* 計算機内部のどこでこの微小差が発生しているのかを突き止め、レーン別 fan 実装時の二重補正やズレを防止する。

### タスク 3: S3 のスキル発動ビート乖離（バー増分がポップ合計を約10%上回る）の究明
* アクション2dの検査で、S3 の「発動あり & 5レーン揃う」3 ビート（b63, b71, b141）だけ比率が **0.83〜0.91** に沈む（バー増分がポップ合計を約10%上回る）ことが判明した。
* fan が原因から除外されたため、真の容疑者である以下を徹底的に点検する：
  1. スキル発動ビートにおけるビートスコア加算の内部仕様（`beatWeightsPermil` の 2000‰ 二重計上疑い等）。
  2. S3 で実測のみ発動しているビート（b32 等）の原因（スキル未習得、CT、スタミナ判定等）。
  3. L2/L4 突出（+9%）がステータスや属性補正（Visual特化 1200‰ / 他 500/300‰）の適用方法に起因していないか。

### タスク 4: S1 のレーン別残分散（L2 0.906 / L5 0.883）とフォト重複規則の決着
* S1 のオフ属性（off-attr: ダンス属性）レーン L2 やバフ無しレーン L5 の残分散を点検。
* S2 の L4（photo fixed + pct 併記）などで生じている局所的なズレについて、固定値（fixed）と割合（pct）の適用順序・合算方式を確定させ、フォト重複モデルを一本化する。
