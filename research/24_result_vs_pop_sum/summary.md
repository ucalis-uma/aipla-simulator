# 24. リザルトレーン別スコア（A）vs ポップ表示合計（B）の整合検証 ― ライブ分析画面バグ仮説の検証

- 作成日: 2026-09-07
- 目的: 「ビートスコア計算・フォトスキルのスタミナ消費ゆれがライブ分析画面（ポップ表示）由来のバグではないか」という仮説のうち、**問題1（ビートスコア計算）**を、
  「リザルト画面のレーン別スコア（真の合計）」と「ライブ中に表示されたスコアポップの合計」の突合で検証する
- 検証対象: T5（qt-daily-003-19）/ S1（qt-area-1-001）/ S2（qt-tower-680）/ S3（qt-ex-tower-005-045）
- 実行: `node research/24_result_vs_pop_sum/analyze.mjs`（丸め判別は `rounding_test.mjs` / `unit_test2.mjs`）

---

## 1. 結論（先に要点）

1. **18/20 レーンで「リザルトのレーン別スコア（A）」が「ポップ表示合計（B）の不確かさ区間 [B_min, B_max]」に収まった**。
   S1・S2 は 10/10 レーン完全整合。T5 は 4/5、S3 は 4/5。
2. 外れた 2 レーン（T5 L5 +1.7%、S3 L3 +12.2%）はいずれも **A > B_max（リザルトの方が大きい）**で、
   「ポップに表示されずリザルトに計上されたスコア」（hidden スコア）が存在することを示す。
   その正体は特定済み:
   - **S3 L3 の超過 1,986,255** ≈ **b2 の A スコア 2,020,432 がフォトポップ（+123.3K）に上書き表示された分**
     （pack_v3 05 §7 で既知の「A ノートとフォト発動が同ビートで重なるとポップは後発行で上書きされる」機構の定量確認）。
   - **T5 L5 の超過 542,678** は L5 発動のスコア獲得フォト 3 ビート（b68/b71/b125）の hidden 計 86,211 + 帰属不明 hidden（b48/b82/b97/b102/b132 の計 7.95M。§5 参照）の一部が L5 側に乗ったと整合する規模。
3. **ポップ表示は K/M/G 単位の「切り捨て」表示と確定**（四捨五入説は棄却）。unit（不確かさ幅）は
   表示の 0.1 桁相当で **K=100 / M=100,000 / G=100,000,000**。「+39K」等の整数表示も `.0` 省略（unit=100）。
4. **hidden スコア（ポップに表示されず bgs に計上されるスコア）の帰属は 15 ビート中 13 ビートで確定/説明済み**
   （§4.3・§5。b97/b132 は L3 crit ビートスコアが発動スコアポップに上書きされたもの・b48/b3 は計上ずれ）。
   残る帰属不明は T5 b82/b102 の 2 件（計 386K）のみ。
5. 以上より、**「ライブ分析画面（ポップ）がビートスコア計算を壊している」という仮説は、
   レーン合計の整合性の観点からは支持されない**。ポップ合計とリザルトは ±0.7% 以内（S1/S2 は ±0.02% 級も含め全レーン区間内）で整合し、
   乖離は「表示の切り捨て + スコア獲得スキル発動時のポップ上書き + 計上ずれ」という**表示仕様**で説明できる。
   （問題2 のスタミナ消費ゆれ検証は本検証では未実施・§7 参照）

## 2. 検証方法

### 2.1 定義

| 記号 | 定義 |
|---|---|
| **A** | リザルト画面のレーン別スコア（`measured_data.results.scores_by_lane` / `lane_scores`。1 の位までの実数） |
| **B** | そのレーンのスコアポップ（ビートスコア + A スキル + SP スキル + P/フォトの score_get 発動スコア）の表示値合計 |
| B_min | Σ(表示下限値) — 表示は切り捨てなので真値は必ずこれ以上 |
| B_max | Σ(表示下限値 + unit) — 真値は必ずこれ未満 |
| 判定 | A ∈ [B_min, B_max] なら「ポップ合計はリザルトと整合（丸めの不確かさの範囲内）」 |

### 2.2 セル分類（ビート×レーンの 795〜885 セル）

| 状態 | 意味 | 扱い |
|---|---|---|
| readable | ポップ表示あり（backfill + measured 既存記録） | lo=表示下限, hi=lo+unit を B に加算 |
| zero | ビート合計 0（開始ビート/全 miss）、A/SP FAIL、A/SP 非発動レーン | 0 として確定扱い |
| unknown | ポップなし・スコアあり（マスク/遮蔽/取り逃し） | §3 の推測で区間化。推測不能なら未解決 |

### 2.3 丸め unit の統計的判別（`unit_test2.mjs`）

「5 レーン全部 readable」のビートで D = bgs − Σ(表示下限) の分布を分析:
- 全セルが小数付き K 表示のビートのみの D 分布は [76, 500) に集中し、山の中心は 5 セル × 一様 [0,100) 端数の和として期待される [200, 300) に一致（T5 n=29・S1 n=85・S2 n=87・S3 n=78）。
- **D < 0 が 0 件**（全サンプル全ビート）→ 切り捨て確定。四捨五入なら D ≈ −250 を中心に負値が約半分出るはずが全く出ない。
- 整数 K 表示（+39K 等）を含むビートでも D が 500 を超えない（S1 max=353 / S2 max=380）→ 整数表示も unit=100（`.0` 省略）で、unit=1000 説は反証。
- 四捨五入仮説での合格率は T5 49/119・S1 67/147・S2 67/140・S3 73/140 と大半不合格 → 棄却。

### 2.4 unknown セルの推測（`guesses.json` に理由を全件記録）

優先順に適用（tier1 で候補がなければ tier2 → 3 → 4）:

| 手段 | 条件 | 実績 |
|---|---|---|
| 同条件参照(tier1) | 同レーン・同ノーツ種・**stat_value・コンボクラス・スコア影響バフ段（beat_score_up/score_up/combo_score_up/tension/boost/focus/stealth/crit係数 の全段）・crit 状態**が完全一致する readable セル群 → min/max ×乱数幅 [0.95, 1.05] | T5 28 / S1 11 / S2 13 / S3 13 |
| 同条件参照(tier2) | tier1 からバフ段一致を外す（stat+コンボクラス+crit 一致） | T5 2 |
| 同条件参照(tier3) | さらに crit 制約を外す（crit フラグ記録なしセルの推測） | S1 5 / S3 2 |
| ビート内残差絞り込み | unknown が 1 つだけのビートで、bgs − 他レーン表示区間 の残差と同条件推定の交差（hidden ありビートでは不使用） | T5 5 / S1 6 / S2 4 / S3 5 |
| 推測不能 | 上記すべてで候補なし | 0 件（全セル推測完了） |

- crit 状態は 3 値で扱う: `crit`（黄ポップ検出）/ `white`（白ポップ検出）/ `unknown`（ポップ自体が見えない no_pop セル）。T5 の no_pop セルは crit 判定不能のため、crit 制約なしの候補集合を使う（誤推測防止・区間は広くなる）。
- 隣接ビートの平滑化は禁止（backfill 規約どおり）。近傍実測の min/max と乱数幅のみで区間化する。

## 4. NG 2 レーンの原因特定

### 4.1 S3 L3: b2 の A スコアがフォトポップで上書き（確定）

- S3 b2 は A ノーツ（chart b2 pos1 → 実レーン L3）。A スコア 2,020,432 はビート合計（bgs=2,662,587）に計上されている。
- しかし同ビートでフォトスキル（127,444）が発動し、**L3 のポップはフォト分 +123.3K のみが表示され、A 分は表示されない**（pack_v3 05 §7 で観察済みの「後発行で上書き」機構）。
- これにより L3 のポップ合計から A スコア 2.02M が欠落 → 超過 1,986,255 ≈ 2,020,432 −（丸め端数 + 上書きフォト分の端数）として説明がつく。
- 同機構は T5 b3（b2 発動の A 24.5M が b3 計上・L3 ポップ +24.5M は b2 に表示済み）でも hidden 24.84M として観測される。

### 4.2 T5 L5: スコア獲得フォト発動ビートの hidden（部分説明）

- L5 はスコア獲得スキル付きフォトを 4 枚装備（40%/40%/85%/45%）で発動 10 回。発動ビートのうち
  **b68（hidden 46,050）・b71（34,396）・b125（5,765）** で「発動レーンのビートスコア分がポップに現れない」欠落が確定
  （発動スコア表示 + ビートスコア計上のズレ。S3 b63/b71/b141 と同型・L5 ビートスコア ~47K と hidden が一致）。
- 確定分 86,211 に対し超過は 542,678。残り 456,467 は帰属不明 hidden 2 件（b82 133,962 + b102 251,947 = 385,909）が
  L5 に乗ればほぼ説明できる規模だが、**b82/b102 には L5 発動記録がなく帰属は未確定**【Unknown】。
- L5 は unknown セル 0 で B が全 readable 由来のため、この超過は「表示されないスコア」の実在を裏付ける。

### 4.3 b97/b132 の白確定と hidden 帰属の確定（2026-09-07 ユーザー情報「b97/b132 はどちらも白」を反映）

- b97（bgs 6,036,771）・b132（bgs 9,860,537）は L3 の「強化効果延長スキル」発動ビート。
  L3 の該当フォトは **小美山愛&赤崎こころ（誰かがクリティカル係数上昇状態の時 20%のスコア獲得 + 自身の強化効果 5 延長・CT50）**。
- L3 ポップは b97 +3.3M / b132 +5.6M（白確定）。このポップを「発動スコアのみの表示」と解くと、
  bgs から発動スコアと他レーン表示区間を除いた **L3 ビートスコアの推定値**は:
  - b97: **[2,359,386, 2,535,306]** — 近傍 L3 crit ビート（b95 2.5M / b96 2.4M / b98 2.5M）と完全に一致
  - b132: **[4,008,337, 4,008,737]** — 近傍 L3 crit ビート（b130 4.2M / b131 4.1M / b133 4.0M）と完全に一致
- つまり b97/b132 の L3 は **crit 級のビートスコアが発生していたが、発動スコアのポップが上書き表示したため
  ビートスコア（とその crit 色）はポップから観測不能になり、bgs にのみ計上された**。
  hidden 2,259,386 / 3,908,337 は **L3 帰属で確定**。
  「white 表示なのに crit 級スコア」という矛盾は、ポップ上書きによりビートスコアの色が観測不能だったことで解決
  （yellow_lanes は表示されたポップの色を記録するもので、上書きされたビートスコアの crit を反映しない）。
- 同様に **b48 の hidden 1,397,982 も L3 帰属で確定**: b47（A ビート）の L3 crit ポップ +1.4M が
  b47 の bgs（4,267,432 = A ポップ区間内のみ）に含まれず **b48 に繰り延べ計上**されている
  （ペア検証: b47+b48 合計 6,783,894 ∈ ポップ区間 [6,626,100, 6,826,500] ✓）。
  b3 の hidden 24,841,167 も同型（b2 発動 A(L3) 24.5M が b2 で表示・b3 で計上）。
- **新知見（計算機側）**: スコア獲得フォト発動ビートでは「発動スコアがビートスコアポップを
  （crit/white に関係なく）完全に上書きする」。発動スコア自体は crit ビートスコアの ~1.4-2.8 倍
  （3.3M/5.6M vs crit ビート 2.4M/4.0M）の巨大値で、発動スコアへの係数適用（crit の有無・B1 構造）は未解明【Unknown】。
  なお b97/b132 の発動スコアに crit 係数を仮に適用すると B1 相当は b97 ≈ 2.97 / b132 ≈ 5.04（crit 2000/2250‰ 除算）となり、
  b132 の方が crit 係数が高いのに発動スコア比率が大きい = 単純な crit×B1 モデルでは説明できない。

## 7. 制限と次のステップ

1. **問題2（フォトスキルのスタミナ消費ゆれ）は本検証の対象外**。ユーザーの指摘どおり再現実験（分析画面のスタミナ表示 80% 以上・実値 80% 以下の条件スキルの挙動）が必要。
2. 本検証は「レーン合計」の整合性検証であり、**個々のビートスコアの正しさは検証していない**
   （ビート単位の検証は research/23 の pack_v1〜v3・純白ビート分析が担当）。
   レーン合計が整合しているということは、**ポップ表示 → 合計の経路にビートスコア計算の系統バグは存在しない**ことを示す。
   ビート単位で±5%乱数を超える乖離が research/23 で議論されているが、それは「basic 計算式の係数（λ・off-attr 扱い・フォト重複規則）」の問題であり、
   「分析画面が引き起こすバグ」とは独立の論点。
3. ~~T5 b97/b132 等の帰属不明 hidden~~ → **解決済み（§4.3）**: ユーザーの白確定情報により crit 取り逃し説は不要。
   b97/b132/b48 の hidden は「L3 crit ビートスコアのポップ上書き / 計上ずれ」で L3 帰属が数値的に確定。
   残る帰属不明は b82（134K）・b102（252K）のみ。
4. hidden スコア機構（発動ビートでのビートスコアポップの上書き消失）は、レーン別ポップから
   正確なスコアを復元するうえで今後の撮影・解析でも考慮が必要（発動ビートの発動レーンポップは
   「ビートスコア+発動スコア」ではなく「発動スコアのみ」として読むべき。crit 発生ビートでも同様）。
   発動スコア自体の係数構造（b97 3.3M = stat 2,348,336 × 20% × ~7.0 倍ファクター）は未解明【Unknown】。
