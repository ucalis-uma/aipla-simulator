# Phase 16 アクション2d: レーン別スコアポップの受け入れ検査（層別化が偽異常を生んでいた）

実行: 2026-09-30 ／ 対象: S1, S2, S3, S4 ／ ツール: **`tools/dump_lane_pops.mjs`**（新規・read-only）
出力: `research/23_beat_score_analysis/phase16_lane_pops_audit.txt`

## 1. 結論

1. **実測データは健全**：5 レーンすべてポップが読めたビートでは
   **レーンポップ合計 ≒ スコアバー増分（`beat_gained_score`）**が成立（中値補正で 0.9965〜1.0000）。
   つまり「レーン別ポップの欠損」ではなく **読み取り可能なレーン数のバラつき**が被覆率の差だった
2. **層を混ぜてはいけない**：レーン数 n で層別化する前は見かけ上 0.6〜0.8 に落ちるが、
   それは n<5 の層（読めないレーン分の単純不足）が混ざっているだけ。
   **`pop合計/バー増分` が 0.43 だった S1 の異常（旧 catalog の A1・Q4）は、
   ① audience 誤入力（+127%）と ② この層の混在 の合わせ技だった**（①は `phase16_action2b_s1_audience.md`）
3. **S4 は検証能力が弱い**（5レーン揃うのが 15/167 ビート）→ AGENTS.md の「ポップ記録の重要さ」は
   S4 で実証された通りになっている。S1/S2/S3 は 140〜147/167〜177 ビートで健勝

## 2. n 層別の `popΣ/barΣ`（中値補正 = 表示値 +50/ポップ）

| サンプル | n=5 発動なし | n=5 発動あり | n=4 | n=3 | 5レーン揃うビート |
|---|---|---|---|---|---|
| S1 | **0.9965**（147件・中央値 0.998） | n=0 | 0.8940（6件） | 0.6931（5件） | 147 / 177 |
| S2 | **1.0000**（140件・中央値 0.998） | n=0 | 0.8726（4件） | 0.5127（3件） | 140 / 168 |
| S3 | **1.0000**（137件・中央値 0.999） | **0.8854**（3件） | 0.7372（5件） | 0.4088（1件） | 140 / 170 |
| S4 | 0.9998（15件） | n=0 | 0.6389（4件） | 0.8024（34件） | **15 / 167 ★** |

- **S1 の n=5 で唯一の外れは b2（0.601）**：中央値は 0.998 なので b2 は単発（ライブ冒頭で
  ポップの一部が未捕捉の可能性）。異常 catalog 入りは不要
- **S3 の発動あり 3 件だけ 0.83〜0.91 に沈む**（b63 0.908 / b71 0.894 / b141 0.831）：
  スキル発動ビートではバー増分がレーンポップ合計を ~10% 上回る。
  → **`beatWeightsPermil`（S3 の 2000‰ 二重計上疑い）を追う際の最有力の手がかり**。
  S3 の L2/L4 突出（+9%）と同じ領域なので、`--samples=S3` の層別解析で同時に当たるとよい

## 3. データ源的な注意（工具を作る過程で判明）

**ポップの格納場所がサンプル間で違っていた**（`dump_lane_pops.mjs` は両方読む）:

| サンプル | `measured_data_v*.json` 側 | `lane_pops_backfill.json` 側 |
|---|---|---|
| S1 | `gained_score_pop` は色のみ（text なし） | **text はここだけ**（777 セル） |
| S2 | v3 の lanes に `{text,color}` あり（735） | text あり（735） |
| S3 | **v3 の lanes に `{text,color}`（733）** | 57 セルだけ（遡及の一部） |
| S4 | 色のみ | 374 セル（`no_frame` 400 ＝ フレーム自体が無い） |

→ **「measured_data に pop が入っているから記録済み」と思って他サンプルを見ると空**という
事故が起きる。統合は `collectPops()` が吸収しているので再発しない

## 4. 使い方

```
node tools/dump_lane_pops.mjs              # S1,S2,S3
node tools/dump_lane_pops.mjs S1,S2,S3,S4  # 全サンプル
```

- `aipura_nox/サンプルN/measured_data_v3.json → v2 → .json` の順に新しい方から timeline を読み、
  `lanes[].gained_score_pop.text`（`+38.6K` 形式）と `lane_pops_backfill.json` の `pops[].displayed` を
  `beat:lane` キーで統合（measured_data 側が優先）
- 出力は (1) レーン別の読めた件数 (2) n 層別の `popΣ/barΣ` (3) n=5 層の乖離上位
- **`audience` の監査は `tools/audit_audience.mjs`**（別工具・`phase16_audience_audit.txt`）
