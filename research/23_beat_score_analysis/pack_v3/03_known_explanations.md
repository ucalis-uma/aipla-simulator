> 検証値の出典はすべて `verification/gen_pack_v3_tables.mjs` の機械出力

## 1. 検討済み・棄却済みの説

### 1.1 κ モデル（off 属性の重み引き下げ）→ 棄却

`basic = floor((own + floor(off × κ/1000)) × 8/140)` の κ をサンプル横断で単一化する試み。

```
S2 (qt-tower-680):
  kappa=1000: n=32 mean=1050.4 sd=15.9 in=15/32 [1017, 1078]
  kappa=900: n=32 mean=1110.5 sd=17.4 in=0/32 [1075, 1140]
  kappa=850: n=32 mean=1143.2 sd=18.3 in=0/32 [1107, 1174]
  kappa=800: n=32 mean=1178.0 sd=19.2 in=0/32 [1141, 1210]
  kappa=700: n=32 mean=1254.1 sd=21.4 in=0/32 [1215, 1289]
  lam=1/20 k=1000: n=32 mean=1200.4 sd=18.2 in=0/32 [1162, 1232]

S3 (qt-ex-tower-005-045):
  kappa=1000: n=70 mean=1003.0 sd=13.7 in=70/70 [963, 1032]
  kappa=900: n=70 mean=1038.9 sd=13.5 in=58/70 [1003, 1063]
  kappa=850: n=70 mean=1057.7 sd=13.7 in=20/70 [1025, 1082]
  kappa=800: n=70 mean=1077.4 sd=14.1 in=4/70 [1044, 1103]
  kappa=700: n=70 mean=1118.8 sd=15.5 in=0/70 [1079, 1149]
  lam=1/20 k=1000: n=70 mean=1146.4 sd=15.6 in=0/70 [1101, 1179]
```

- S3 は κ=1000 で 70/70（平均乱数 1003.0）= **off 引き下げなし**が正しい
- S2 は κ=1000 で平均 1050.4（全ビート正側）で、κ を **上げる（≈1080）方向**でしか
  直らない。過去の検証で「別ステージは κ↓ が要求される」との主張があったが、
  S2（κ↑）と S3（κ=1000）だけで **単一 κ のサンプル横断解が存在しない**ことは確定しており、
  S3 だけでも κ モデルの導入根拠がない（2026-09-05 の外部 LLM 統一モデル提案に対する
  検証で確定。pack_v2/05 §2.1 参照）

### 1.2 フォト固定値（beat_score: fixed）のビート常時加算 → 棄却

deck.json にはフォトの「ビートスコア（固定値）」項目が存在する
（S2: L2 +474 / L4 +1150 / L5 +1378。S3: L2 +3598 / L3 +920 — deck.json の
`beat_score/fixed` 合計を機械抽出）。これをレーンイベントに加算すると:

```
S2 flat per lane (deck.json beat_score/fixed sum): {"2":474,"4":1150,"5":1378}
- no-flat: n=32 mean=1050.4 sd=15.9 in=15/32 [1017, 1078]
- flat-per-lane-event: n=32 mean=1016.1 sd=14.9 in=32/32 [989, 1042]

S3 flat per lane (deck.json beat_score/fixed sum): {"2":3598,"3":920}
- no-flat: n=70 mean=1003.0 sd=13.7 in=70/70 [963, 1032]
- flat-per-lane-event: n=70 mean=982.9 sd=13.8 in=69/70 [946, 1013]
```

- S2 は 32/32・平均 1016.1 に「収まるように見える」が、S3 は 70/70 → 69/70・平均 982.9 に
  **悪化**する。両立しないため S2 の一致は数値の偶然 → 棄却
  （これらの fixed 値はフォト P スキルの score_get（発動時 1 回の固定スコア）値であり、
  パッシブ常時加算ではない — S1 の A スコア固定値と同型の発動型として実装済み）

### 1.3 λ = 1/20（コミュニティ資料「やる気士 docs」の定義）→ 棄却

やる気士 docs の定義 `basic = S_center×3.0% + S_sub×1.25% + S_weak×0.75%` は
マスタ重み（600/250/150‰）× 1/20 と数学的に等価。しかし:

- S3（重み和 2000‰）で λ=1/20 は −14.3%（平均 1146.4 = 実測比・全滅）
- T5 では λ=8/140 で全 3000 イベントが乱数内に収束（ゴールデンスコア 1 の位まで一致）
- **1/20 説は S3/T5 と矛盾**

### 1.4 λ = 8/ノーツ数（ノーツ数等分説）→ 棄却

- S2 の通常ビート数は 149、S3 は 148 — ほぼ同数だが適合 λ が異なる
  （S3 は 8/140 相当で 70/70、S2 は同じ 8/140 で +5.04% シフト）
- ノーツ数で等分するモデルではこの差を説明できない（pack_v2/01 の反証を S2/S3 の範囲で再録）

### 1.5 フォト beat% の sum 適用（全レーン一括切替）→ 棄却

- S3-L4 b8 の実測ポップ 86.3K に対し、現行実装（max 規則・B1 = 1000+60+193+... に相当）では
  比率 0.982（乱数内一致）。sum 規則では 1.114 となり**全乱数域でオーバー**
- 本 pack のデータでも同一結論: S3 ビート表の b8 L4 ポップ +86.3K はレーン別 implied rand
  1018.3（ポップ表示の下限値基準）として再現される
- また sum/max の一括切替は S2 のレーン構造（L4 のみ 2 枚装備でも L2/L3/L5 が同様にずれる）
  を説明できない

### 1.6 乱数分布自体の偏り → 棄却

- S2 の 32/32 全ビート正側は偶然の確率 2^-32 であり、かつ sd 15.9‰ は乱数本来の広がりと
  同程度（分布の形は正常・中心だけがずれる）
- 一方 S3 の 70 ビートは [963, 1032] にほぼ対称に分布 → ゲーム全体の乱数中心は 1000 のまま
- S2 固有の環境要因（ステージ・デッキ・レーン構成）が原因

### 1.7 既知の S2 全体ギャップ（未解明のまま残る事実）

- S2 は楽曲全体でも sim 側が低い既知ギャップがある: crit フラグ再現ラン 75,656,769 vs
  実測 77,732,383 = sim/実測 ×0.973（全レーン ±5% 内だが L5 ×0.952〜L4 ×0.962 と
  低めに偏る・research/12 Phase 11）
- 純白ビートの +5.04% シフト（実測 > sim）と**同方向**。スキルノーツは全件乱数内合致のため、
  ギャップは通常ビート系（basic またはレーン別乗算ファクター）に局所される

## 2. pack_v3 の新知見: シフトは「レーン別定数オフセット」構造を持つ

レーン別ポップ完備（S2 840/840・S3 850/850 セル）により初めて分解できた事実（02 §1/§4.2）:

| lane | S2 offset | S3 offset | S2 レーン属性 | S3 レーン属性 |
|---|---|---|---|---|
| L1 | +1.5‰ | -49.4‰ | vocal | visual |
| L2 | +61.9‰ | +84.5‰ | vocal | vocal |
| L3 | +20.2‰ | -46.2‰ | vocal | visual |
| L4 | +67.4‰ | +73.9‰ | dance | visual |
| L5 | +95.9‰ | -54.6‰ | vocal | visual |

- **S2 は L1 を除く 4 レーンが正側**（L1 +1.5 はほぼ 0・L5 は 32/32 が 1050 超）。
  ビート合計の +50.4 はこのレーン別オフセットの加重平均
- **S3 は混号**（L2/L4 正・L1/L3/L5 負）でビート合計（70/70・平均 1003）では相殺。
  L2・L4 は両サンプルで正側
- レーン別 implied rand の sd（29-34‰）= 一様乱数 [950,1050] の理論 sd 28.9‰。
  ビート合計の sd（S2 15.9 / S3 13.7）= 5 独立乱数平均の理論 sd 12.9‰。
  → **各レーンの乱数抽選自体は正常で、レーンごとの定数オフセットが乗る**構造
- ポップ表示の切り捨て分解能（K 桁で ±0.1K ≒ ±0.15% 以下）はオフセット
  （最大 +96‰）より 1 桁以上小さく、説明にならない
- S2 backfill の品質は色 × 判定フラグ突合（不一致 1 件のみ・b12 L2 は拡大再確認で
  既存フラグ = yellow が正と判明・訂正済み）と K 単位合計照合（over-sum 0 件）で担保済み

## 3. したがって次の問いは

「単一の λ/κ/規則の差し替え」では説明できないため、04a/04b では
**S2（+S3 対照）のレーン別系統的オフセットを説明できる仕様レベルの仮説の列挙と、
各説の判定に使える追加データ/実験の提案**を外部の分析に依頼する
（λ・κ・フォト規則の再推定や統一モデルの全面再構築は依頼しない）。
