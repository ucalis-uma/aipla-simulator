## 2. 隠れ 3 セルの特定と因子

### 2.1 特定

`tools/audit_hidden_cells_sim.ts` のセル（sim がイベントを持つ `beat:lane`）のうち、pop が
読めていない L3 セルは 153 セル中 **3 セルだけ**（監査の `隠れセル 3 セル` と一致）:

| セル | sim | 内訳 | 実測側の状況 |
|---|---:|---|---|
| **b1:3** | 35,898 | beat のみ | b1 は**5 レーン全て pop 不能**（開幕バーストでポップ欄が埋まる）。note「banner発動者は肖像サムネイル2枚より同定」 |
| **b13:3** | 41,048 | beat のみ | L1/L2/L4/L5 は可読（+30.2K/+38.4K/+93K/+60.4K）。L3 だけ不能（P スキル再発動ビート・note に pop の記載なし） |
| **b73:3** | 39,093 | beat のみ | L1/L2/L4/L5 は可読。L3 だけ不能（P スキル再発動・集目 6→10 段更新） |

因子ダンプ（`cellEvents`）: 3 セルとも `sourceKind:"beat"`・`critFactorPermil:1000`（非クリ）・
`fanFactorPermil:1375`・`b1Permil:1484`（S3 のライブ特徴「ビートスコア 2.0 倍」）。

```
b1 :3 beat basicScore 17,593 skillPower 1000 b1 1484 combo 1000 fan 1375 → 35,898
b13:3 beat basicScore 19,159 skillPower 1000 b1 1484 combo 1050 fan 1375 → 41,048
b73:3 beat basicScore 19,159 skillPower 1000 b1 1484 combo 1000 fan 1375 → 39,093
```

### 2.2 実測側の独立推定（上界検定）

「そのレーンで pop が不能なビート」の残差 `R_b = beat_gained_score − Σ(可読 pop)` は、
そのビートで**全レーン合計として未記録**の額（K/M 切り捨ての分だけ上界）。L3 の 20 不能ビート
（b0 を含む・実質 19 本）で合計しても **529,839** にしかならない:

| ビート | 残差 R_b | 可読レーン | L3 sim | L3 の実測推定 |
|---|---:|---:|---:|---|
| b1 | 218,749 | 0/5 | 35,898 | 5 レーン合計 218,749（sim 5 セル合計 215,912）→ **b1:3 ≈ 35,898 で整合** |
| b13 | 43,764 | 4/5 | 41,048 | **L3 のみ不能 → 実測 ≈ 43,368〜43,764（sim −5.3〜−6.2%）** |
| b73 | 64,301 | 4/5 | 39,093 | **L3 のみ不能 → 実測 ≈ 63,905〜64,301（sim −38.8%・絶対差 25,208）** |
| b4/b14/b34/b42/b51/b81 | 7,151 / 51,809 / 46,467 / 15,072 / 67,197 / 15,329 | 1/5 | セルなし | 可読 1 レーンの pop が `beat_gained_score` をほぼ説明（多くは M/K 切り捨て）→ L3 ≈ 0 |
| b60/b70/b83/b93/b103/b113/b133/b142/b150/b160 | 0 | 0/5 | セルなし | `beat_gained_score = 0`（FAIL/コンボ断絶ビート・`supplement.fail_beats` と一致）→ L3 = 0 |

→ **隠れ 3 セルは「sim が実測より多く置いている」方向の異常ではない**（b13/b73 はむしろ sim が少ない）。
b73 の 25,208 の差は【Unknown】（P スキル再発動ビートの加点機構か、L3 以外の可読 pop の
読み残しかを切り分ける材料が無い。3 セル合計でも 25K = レーン合計の 0.14%）。

**決定的な事実**: 隠れ枠（分母）2,635,445 に対し、L3 の不能ビートで説明できる上限は 529,839。
**分母の 80% は「不能セル」以外の場所にある。**

### 3.2 sim 側

| セル | sim のイベント内訳 | 実測の推定 |
|---|---|---|
| `2:3` | photo 111,757（power 400‰）＋ **A 1,771,743（power 5100‰・非クリ）** = **1,883,500** | pop 123,300 ＋ 未記録 A 2,085,210 ≒ 2,208,510 |

## 5. ゲートの精緻化（`tools/audit_hidden_cells.mjs`）

手順書の指示（「(b) ならゲートの除外条件を精緻化する（上側の閾値・分母は絶対に動かさない）」）に従い、
**分母（`レーン合計 − Σpop`）と閾値（上 2.0/1.5・下 0.25/0.5）は 1 も変えず**、分子を対称化した:

```
R_b = max(0, beat_gained_score_b − Σ(pop 可読セル))     ← 実測が「未記録」と証明した額
H_b = sim(pop 不能セル)                                ← 従来の分子
E_b = Σ_{pop 可読セル} max(0, sim − pop)                ← sim の pop 超過
分子 = Σ_b [ H_b + min(E_b, max(0, R_b − H_b)) ]
```

- `min(…) ≥ 0` なので **新分子 ≥ 旧分子**。上側（過剰配置の検出）は**厳しくなる方向にしか動かない**
  （A8 の 7.69× のような回帰は従来どおり検出される。実際 S3 L1 は 0.45× → 1.44× に上昇）。
- 「実測が未記録と証明した額」を上限にすることで、**単なるモデル誤差（S1 L3 の b115 +430,594 等）を
  過剰配置と誤認しない**（S1 L3 は 0.00× → 0.57× に留まる）。
- 現行比（`simHidden / 隠れ枠`）も全行に併記するので、差分は常に監査できる。

実測値（`npm run audit:hidden -- --low-gate=warn`）:

```
FAIL（比 ≥ 2.0）= 0 / WARN（1.5 ≤ 比 < 2.0）= 0            ← 上側 PASS（最大 1.44× = S3 L1）
【下側】FAIL（≤ 0.25）= 1 件: S2 L3 0.22×（現行比 0.19）    ← S3 L3 は 0.75× = OK になった
【下側】WARN = 0 件
S3 L3 | 比(対称) 0.755× | 比(現行) 0.04 | 可読比 1.050 | レーン比 0.906（未説明 1,731,274）
  └ 対称分子の内訳: sim(不能) 116,039 + 可読セル超過の実測証明分 1,872,923 = 1,988,962（分母 2,635,445 は共通）
```

**残る下側 FAIL は S2 L3 0.22× の 1 件だけ**（＝ A2 の担当）。

## 6. A2 への引き継ぎ（この節はタスク A2 の入力）

1. S3 L3 の不足 1,731,274 はほぼ**可読セル側**（A スキル 4 セルで −0.87M・§3.3）。
   隠れセル側の不足は最大でも 0.53M（§2.2）。
2. A スキルは `skillPowerPermil` が 4700〜5100‰（= 累積比参照）。sim の参照点
   （`state.scoreCumAtSkillStart`）が**同一ビート内で先に適用された他スキル分を含んでいない**疑い。
   b24/b79/b169/b2 の 4 セルは「同一ビートに他レーンの A/SP が居るか」で切り分けられる。
3. S2 L3 の下側 FAIL（226,012 の隠れ枠に対し分子 50,643）は**別系統**。A12 の lanefans 口径で
   SP 1 セル 707,502 の不足として出ている事象と同一レーンなので、A2 で併せて見る。
