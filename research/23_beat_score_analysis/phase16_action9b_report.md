### 1-2. 裁定: **①（自己バフ課金）は反証。②（持続境界）が支持される**（機構は「減算順序」）

**(a) ①の反証（3 つの独立証拠）**

1. **付与先が違う**: S1 の同フォト 3 発動（b1/b60/b120）の実測 act 行は
   `「ボーカルタイプ1人にボーカルブースト効果[22ビート]」/ targets=ボーカルタイプ1人（=L3）`。
   発動レーン L1 自身には付与されない（`_out.txt` §[2b]）。自 act の付与を自分のコストに足す規則では
   L1 の 681 は原理的に出ない（L3 のコストにしか効かない）。
2. **自付与はコストに入らない**: S1 b66/b123/b176 の A スキル「夏を先取りお祭り騒ぎ」（自分に 4 段ボーカルブースト）は
   実測 **165/169/169 = 原価×1.03/1.0242**（＝既存の他ソース 3 段のみ）で、b123 の表示は**発動後 7 段**（3+自付与 4）。
   実測は 3 段ぶんしか課金していない＝**自付与はコストに不算入**。
3. **段数の偶合**: A9 が ① と読んだ根拠「snapshot の 3 段 = フォトの 3 段」は、実際には
   L2 の A スキル「準備も立った大舞台」（b25 付与・3 段・36 ビート）が b60 に残っていたもの
   （engine トレース: `vocal:3段(rem35)@麻奈も立った大舞台` → b60 で `rem0`）。

**(b) ②の支持と機構の特定**

- 実機表示: L1 の `ボーカルブースト 3` は **b25〜b60 に表示され、b61 で消滅**（S1 timeline を直接読取）。
  ＝ 申告 36 ビートどおりで、engine のビート別 snapshot（step7）のライフタイムとも一致する。
- engine も同じインスタンスを **b60 の step7 snapshot には持っている**（`buffSnapshots` の倍率は 1030‰）。
  しかしこのフォトは CT=60 のため **step11（phase=last）に発火**し、`snapshotOf` は step10 の減算後
  （`remainingBeats` が 0 に落ちた後）なので `remainingBeats > 0` フィルタで落ちる → 662。
  同じ phase=last でも b120 は boost が寿命途中（rem19）なので 681 になる。
- したがって **「持続を 1 ビート延ばす」のではなく、「最終ビートの表示状態が、そのビートの後半発動の
  コストにも有効」という順序の問題**である（手順書の ② を、より狭く正確に特定した形）。
  b120 が一致し b60 だけが外れる、という A9 の残差（+2.87%）と整合。
