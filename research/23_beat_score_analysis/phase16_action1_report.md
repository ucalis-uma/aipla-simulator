## 1. 方法と正当性（self-check）

`src/` は恒久変更しない。エンジン出力トレースのファクターから各モデル値を**厳密に**再計算する。

- λ は基本項にのみ作用: `basic = floor(basicSum × λnum/λden)`（8/140 = 1/17.5 ↔ 1/20 は **比 0.875**）
- フォト max/sum は B1 にのみ作用: `scoreBonusPct.beat` の写/アクセ由来項を
  `max(pct)`（現行）↔ `sum(pct)`（docs）に差替え、その差分 Δ‰ を `b1Permil` に加算
  （取得はエンジンと同じ `structured: [{stat:"beat_score", type:"pct"}]`・photos+accessories）
- 比較ランは **実測クリティカル再現 ＋ 乱数中立（rand=1000）**。実測側は事象毎に rand∈[950,1050] を
  引くため、式が正しければ**全ビート**で sim/meas ∈ [0.9500, 1.0500]（平均判定は禁止）

**self-check（再計算機構がエンジンを厳密に再現している証明）** — 全サンプルで不一致ゼロ:

| サンプル | beat イベント照合 | その他イベント照合 | 不一致 | 検証不能 |
|---|---|---|---|---|
| S3 | 740 | 16 | **0** | 0 |
| T5 | 685 | 32 | **0** | 0 |
| S2 | 745 | 18 | **0** | 0 |

S3 のリプレイ総スコア **78,485,270** は保存トレース
（`research/21_sample3_gap_analysis/sim_trace_full.json` の `simTotal`）と**完全一致**。

## 3. フォト `beat_score` の max / sum 判定 → **判別不能（max 維持）**

### 3.1 判別に使えるセルが極端に少ない

`equipmentForScore`（写真＋アクセサリ）の `beat_score`% をエンジンと同じ規則で抽出した結果:

| サンプル | L1 | L2 | L3 | L4 | L5 | 判定に使えるレーン（2枚以上） |
|---|---|---|---|---|---|---|
| S3 | − | − | 24.9 | **17.5 + 19.3** | − | **L4 のみ**（max 19.3 / sum 36.8 → Δ +175‰） |
| T5 | − | − | − | − | − | **0**（T5 編成に beat_score% 写真なし） |
| S2 | 20.7 | 17.7 | 19.3 | **17.5 + 20.6** | 15.6 | **L4 のみ**（max 20.6 / sum 38.1 → Δ +175‰） |

1枚のレーンは max = sum であり原理的に判別不能。実質 **S3-L4 と S2-L4 の 2 セル**だけが判別材料。

### 3.2 ビート合算での優劣（A vs D）

| サンプル | A（max） | D（sum） | 優位 |
|---|---|---|---|
| S3 | 152/159・平均 0.9927 | 133/159・平均 1.0293 | **A**（L4 が +17.5% 過大になり +2.9% の持ち上げ） |
| S2 | 33/165・平均 0.9266 | 85/165・平均 0.9451 | **D**（元々 −7.5% 低いので持ち上げが寄与） |
| T5 | 同一（判別力ゼロ） | 同一 | − |

**S3 は max を支持、S2 は sum を支持**という食い違い。ただし S2 の sum 優位は
「S2 が全体的に −7.5% 低い」ことを L4 の +17.5% で帳消しにしているだけで、
**L4 以外の 4 レーンは A/D どちらでも同一比率**（L1 1.0069 / L2 1.0681 / L3 1.0285 / L5 1.1030）
のまま狂っている。したがって S2 の sum 優位は偽のシグナル（§5 の系統ズレの吸収）と判定する。

### 3.3 レーン別スコアポップでの検証（純白ビート・指標 = 実測ポップ中値 / sim）

| サンプル | nセル | A: ±5% | A レーン別（L1..L5） | D: ±5% | D の L4 |
|---|---|---|---|---|---|
| S3 | 348 | 147/348 | 0.9582 / **1.0945** / 0.9712 / **1.0916** / 0.9463 | 166/348 | 0.9592 |
| T5 | 130 | 119/130 | 1.0100 / 1.0148 / 1.0169 / 1.0015 / 1.0046 | 119/130 | （写なし） |
| S2 | 160 | 61/160 | 1.0069 / 1.0681 / 1.0285 / **1.2171** / 1.1030 | 70/160 | 1.0753 |

- **T5 は全レーン 1.000〜1.017 に揃う**（＝式は正しい。beat_score 写真が無いクリーンな対照群）。
- S3 で **L2（+9.5%）と L4（+9.2%）だけが突出**するが、**L2 には beat_score% が 1枚も無い**
  （＝max/sum のどちらでも動かず +9.5% のまま）。よって S3 の突出は**フォト集計では説明できない**。
- S2 L4 の +21.7% は sum で +7.5% まで縮むが、S2 の他 4 レーンは +0.7〜+10.3% で、
  依然として「全レーンが一様に sim 低い」状態が残る。

### 3.4 判定

- 現行 `max`（`src/sim/build.ts:679`・2026-09-04 の S3 pop 実測確定）を**推翻できなかった** → **変更しない**
- sum を支持する唯一の観測（S2-L4）は §5 の系統ズレの吸収で説明可能 → **sum 採用には否**
- 残る矛盾（S3/S2 で 1 レーンだけ +9〜+22% sim 低い）は**フォト集計とは別の要因**
- 状態: **【Unknown】**。判別するには「1 レーンに beat_score% が 2 枚以上、他レーンは 0 枚、
  かつレーン別ポップを全ビート記録した」新規サンプルが必要（`prompts/backfill-lane-pops.md` 併用）

## 4. S3 confirmed ギャップ（−8.62%）の要因分解

### 4.1 3本のランの関係（実測 79,411,389）

| ラン | 総スコア | 実測比 |
|---|---|---|
| 確定値（乱数中立 rand=1000・**crit 発動なし**） | 65,954,705 | **−16.94%** |
| リプレイ（乱数中立・**実測クリティカル再現**） | 78,485,270 | **−1.17%** |
| 実測（保存トレース一致） | 79,411,389 | 基準 |
| （仕様書記載の旧 sim 確定値 66,378,887 / 記録済み確定値基準 72,176,945） | → −8.24% / **−8.62%** | 基準 |

- クリティカルプレミアム: sim **+12,530,565** / 実測 **+13,456,684**（実測の約 1/6 が crit 由来）
- → **ギャップの 93% はクリティカル倍率の扱い**。確定値ランは crit を発動させないため、
  その分だけ構造的に低くなる（＝式の誤りではない）。

### 4.2 残差 −926,119（−1.17%）のビート種別内訳

| 分類 | ビート数 | sim | 実測 | 差分 | ギャップシェア | 実測総スコア比 |
|---|---|---|---|---|---|---|

- **通常ビート（白）由来の差は実測総スコアの 0.21% だけ**（白ノーツだけのギャップシェア 2.68%）。
