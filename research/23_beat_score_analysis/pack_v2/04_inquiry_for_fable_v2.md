## 1. 確定しているスコア計算アーキテクチャ

アイプラの1回のビート（ノーツ）における獲得スコアは、以下の階層的 floor 構造で計算されることが確定しています：

$$\text{Score} = \text{floor}\left( \text{floor}\left( \text{floor}\left( \text{floor}(\text{basic} \times \text{buff}) \times \text{combo} \right) \times \text{fan} \right) \times \text{stage} \right) \times \text{rnd} \times \text{crit}$$

各要素の仕様：
1. **$\text{rnd}$（乱数）**: 実機仕様は千分率で $950 \sim 1050 / 1000$（$[0.950, 1.050]$、中心値 $1.000$、最大振れ幅 $\pm 5.0\%$、通常は $\pm 4.5\%$）。
2. **$\text{crit}$（クリティカル）**: 通常HIT時は $1.0$。クリティカル発生時はキャラのクリティカル係数（$\ge 1.5$）が乗算される。
3. **$\text{fan}$（ファン数ボーナス）**: 会場来場者数に応じたボーナス（例: 40,000人一律ステージでは $1.375$）。
4. **$\text{combo}$（コンボ倍率）**: コンボ数テーブルに基づく倍率（例: 100コンボで $2.0$）。
5. **$\text{stage}$（ステージ固有倍率）**: 通常は $1.0$。
6. **$\text{buff}$（スコア上昇バフ）**: スキルやフォトによる「ビートスコア上昇%」等の補正 $(1 + \sum \text{buff}_\%) $。
7. **$\text{basic}$（基本スコア）**: 通常ビートの基礎値（**今回の再推定対象**）。

## 2. 通常ビート基本スコア（basic）の既知の定義とマスタデータ

### (1) ゲーム内マスターデータ (`Quest.json`) のステージ重み
ステージごとに `beatWeightsPermil`（属性重み・千分率）が定義されています：
- 通常ステージ（重み合計 1000‰）:
  - センター属性: **600‰ (0.60)**
  - 準属性: **250‰ (0.25)**
  - 劣勢属性: **150‰ (0.15)**
- ビートスコア2倍ステージ（重み合計 2000‰、例: EXタワー ⅢX-045）:
  - センター属性: **1200‰ (1.20)**
  - 準属性: **500‰ (0.50)**
  - 劣勢属性: **300‰ (0.30)**

各レーンのアイドルのステータス（ライブ中バフ前の素ステータスまたは適用後ステータス）を $S_{vo}, S_{da}, S_{vi}$、ステージ重みを $W_{vo}, W_{da}, W_{vi}$（千分率）とすると、重み付きステータス和は：
$$basicSum = \left\lfloor \frac{S_{vo} \times W_{vo}}{1000} \right\rfloor + \left\lfloor \frac{S_{da} \times W_{da}}{1000} \right\rfloor + \left\lfloor \frac{S_{vi} \times W_{vi}}{1000} \right\rfloor$$

### (2) コミュニティ検証資料（やる気士docs）の定義
アイプラの先行研究コミュニティ資料では、通常ビートの基本スコアは以下のように定義されています：
$$\text{basic} = S_{\text{center}} \times 3.0\% + S_{\text{sub}} \times 1.25\% + S_{\text{weak}} \times 0.75\%$$

これはマスタデータの重み（600‰, 250‰, 150‰）と照らし合わせると：
- $600‰ \times 5.0\% (1/20) = 30‰ = 3.0\%$
- $250‰ \times 5.0\% (1/20) = 12.5‰ = 1.25\%$
- $150‰ \times 5.0\% (1/20) = 7.5‰ = 0.75\%$
となり、**「$\text{basic} = \lfloor basicSum \times \frac{1}{20} \rfloor$（基礎係数 $\lambda = 5.000\%$）」** と数学的に完全等価です。

## 4. 明らかになった核心的矛盾：「8/7」の謎

実測から確実に言える数理的事実は以下の通りです：

1. **2つの異なる成立係数**:
   - S4（Dance特化）では **$\lambda = 1/20 = 5.000\%$** が成立する。
   - T5（Vocal特化）および S3（Visual特化）では **$\lambda = 8/140 \approx 5.714\%$** が成立する。
2. **両者の比率は極めてシンプルかつ正確に「8/7」**:
   $$\frac{8/140}{1/20} = \frac{8/140}{7/140} = \frac{8}{7} \approx 1.142857 \quad (+14.286\%)$$
3. **否定された仮説群**:
   - **「曲の通常ビート数 $N_{\text{beat}}$ で等分する説（$\lambda = 8 / N_{\text{beat}}$）」の破綻**:
     S3 の通常ビート数は **148**、S4 の通常ビート数は **149** であり、ノーツ数は実質同数（1ノーツ差）です。もしノーツ数等分なら両者の係数は同一（約 8/148）になるはずですが、実測では S3 は 8/140、S4 は 1/20（7/140）であり、明確に 8/7 の差が生じています。
   - **「モード種別（タワーか否か）」の否定**:
     S3 も S4 も全く同一の「EXタワー（40,000人、fan倍率1.375）」です。
   - **「ステータス計算やバフ・コンボ・ファンの計算誤差」の否定**:
     スキルノーツ（SP/A）は S4 でも全件 100% 乱数内に合致しており、デッキステータスや共通乗算処理に 1% の誤差もありません。差は通常ビートの $\text{basic}$ にのみ存在します。

## 5. フォトスキルのビートスコア上昇%（beat_score）の未解明問題

フォトに付与されるパッシブスキルに「ビートスコア上昇 +X%」が存在します。
S3 のレーン4には、フォトが2枚（17.5% と 19.3%）装備されています。
- **もし $\lambda = 8/140$ の場合**:
  - 2枚の最大値（$\max(17.5\%, 19.3\%) = 19.3\%$）を適用すると、実測ポップ 86.3K に対してシミュレータ値 87.8K（比率 1.018）となり綺麗に合致します。
  - 合算（$17.5\% + 19.3\% = 36.8\%$）を適用すると過大になります。
- **もし $\lambda = 1/20$ の場合**:
  - 合算（$36.8\%$）を適用すると、シミュレータ値 85.3K（比率 0.988）となり、実測ポップ 86.3K と綺麗に合致します。

このように、「基礎係数 $\lambda$」と「フォトスキルの重複ルール（加算 sum vs 単一最大 max）」が密接に連動している可能性があります。
