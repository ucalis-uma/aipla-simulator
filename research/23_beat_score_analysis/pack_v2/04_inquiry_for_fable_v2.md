## 1. 確定しているスコア計算アーキテクチャ

アイプラの1回のビート（ノーツ）における獲得スコアは、以下の階層的 floor 構造で計算されることが確定しています：

$$\text{Score} = \text{floor}\left( \text{floor}\left( \text{floor}\left( \text{floor}(\text{basic} \times \text{buff}) \times \text{combo} \right) \times \text{fan} \right) \times \text{stage} \right) \times \text{rnd} \times \text{crit}$$

各要素の仕様：
1. **$\text{rnd}$（乱数）**: 実機仕様は千分率で $950 \sim 1050 / 1000$（$[0.950, 1.050]$、中心値 $1.000$、最大振れ幅 $\pm 5.0\%$、通常は $\pm 4.5\%$）。
2. **$\text{crit}$（クリティカル）**: 通常HIT時は $1.0$。クリティカル発生時はキャラのクリティカル係数（$\ge 1.5$）が乗算される。
3. **$\text{fan}$（ファン数ボーナス）**: 会場来場者数に応じたボーナス（例: 40,000人一律ステージでは $1.375$）。
4. **$\text{combo}$（コンボ倍率）**: コンボ数テーブルに基づく倍率（例: 100コンボで $2.0$）。
5. **$\text{stage}$（ステージ固有倍率）**: 通常は $1.0$。
6. **$\text{buff}$（スコア上昇バフ）**: スキルやフォトによる「ビートスコア上昇%」等の補正 $(1 + \sum \text{buff}_\%) $。
7. **$\text{basic}$（基本スコア）**: 通常ビートの基礎値（**今回の解析対象**）。

## 2. 通常ビート基本スコア（basic）の既知の定義とマスタデータ

### (1) ゲーム内マスターデータ (`Quest.json`) のステージ属性重み
ステージごとに `beatWeightsPermil`（属性重み・千分率）が定義されています：
- 通常ステージ（重み合計 1000‰）:
  - センター属性: **600‰ (0.60)**
  - 準属性: **250‰ (0.25)**
  - 劣勢属性: **150‰ (0.15)**
- ビートスコア2倍ステージ（重み合計 2000‰、例: EXタワー ⅢX-045）:
  - センター属性: **1200‰ (1.20)**
  - 準属性: **500‰ (0.50)**
  - 劣勢属性: **300‰ (0.30)**

各レーンのアイドルのステータス（ライブ中バフ前の素ステータスまたは適用後ステータス）を $S_{vo}, S_{da}, S_{vi}$、ステージ重みを $W_{vo}, W_{da}, W_{vi}$（千分率）とすると、重み付きステータス和は：
$$basicSum = \left\lfloor \frac{S_{vo} \times W_{vo}}{1000} \right\rfloor + \left\lfloor \frac{S_{da} \times W_{da}}{1000} \right\rfloor + \left\lfloor \frac{S_{vi} \times W_{vi}}{1000} \right\rfloor$$

### (2) 先行研究コミュニティ資料（やる気士docs）の定義
先行研究資料では、通常ビートの基本スコアは以下のように定義されています：
$$\text{basic} = S_{\text{center}} \times 3.0\% + S_{\text{sub}} \times 1.25\% + S_{\text{weak}} \times 0.75\%$$

これはマスタデータの重み（600‰, 250‰, 150‰）と照らし合わせると：
- $600‰ \times 5.0\% (1/20) = 30‰ = 3.0\%$
- $250‰ \times 5.0\% (1/20) = 12.5‰ = 1.25\%$
- $150‰ \times 5.0\% (1/20) = 7.5‰ = 0.75\%$$
となり、**「$\text{basic} = \lfloor basicSum \times \frac{1}{20} \rfloor$（基礎係数 $\lambda = 5.000\%$）」** と数学的に等価です。

### (3) 現行シミュレータの実装値
シミュレータ開発初期の特定テストケース調整において、暫定的に以下の係数が設定されていました：
$$\text{basic} = \left\lfloor basicSum \times \frac{8}{140} \right\rfloor \quad \left(\frac{8}{140} \approx 5.714\%\right)$$

## 3. 実機実測データ（3ステージの検証結果）

実機プレイ動画から、**クリティカルおよびスキル発動を完全に除外した「純粋な白ノーツ（全5レーンHIT）」のみ** を抽出し、計算値と実測値の比率（$\text{ratio} = \text{sim} / \text{actual}$）を検証しました。

### サンプルA: S4（EXタワー Liznoir-054 / 曲: lumiere）
- **ステージ属性**: **Dance特化**（センター属性: Dance）
- **属性重み**: Vo 150‰ / Da 600‰ / Vi 250‰（合計 1000‰）
- **来場者数**: 40,000人（fan倍率 一律 1.375）
- **ノーツ内訳**: 総ノーツ 166（**通常ビート 149** / Aスキル 14 / SPスキル 3）
- **スキルノーツ検証**: SP 3件、A 14件の全17件が、現行のステータス・バフ・コンボ・ファン式で **100% 乱数内（±4.5%）に完全合致**。
- **純粋白ノーツ（67ビート）の実測検証**:
  - **やる気士docs式（$\lambda = 1/20 = 5.000\%$）**:
    - 平均比率: **0.9962（誤差 -0.38%）**
    - 振れ幅: 全67件が $[0.9435, 1.0714]$（$-5.6\% \sim +7.1\%$）に集中し、**乱数中心 1.000 に極めて美しく収束**。
  - **現行シミュレータ値（$\lambda = 8/140 \approx 5.714\%$）**:
    - 平均比率: **1.1385 (+13.85%)** となり、実測より過大。

### サンプルB: S3（EXタワー ⅢX-045 / 曲: Blow Up）
- **ステージ属性**: **Visual特化**（センター属性: Visual、ビートスコア2倍ステージ）
- **属性重み**: Vo 500‰ / Da 300‰ / Vi 1200‰（合計 2000‰）
- **来場者数**: 40,000人（fan倍率 一律 1.375）
- **ノーツ内訳**: 総ノーツ 169（**通常ビート 148** / Aスキル 19 / SPスキル 2）
- **スキルノーツ検証**: SP 2件、A 19件の全21件が **100% 乱数内に完全合致**。
- **純粋白ノーツの実測検証**:
  - **現行シミュレータ値（$\lambda = 8/140 \approx 5.714\%$）**:
    - 実測値との比率: **0.975 〜 1.005（平均 0.990）** で **乱数中心 1.000 に合致**。
  - **やる気士docs式（$\lambda = 1/20 = 5.000\%$）**:
    - 比率: **0.853 〜 0.880 (-13%〜-15%)** となり、実測より過小。

### サンプルC: T5（デイリーライブ STAGE19 / 曲: サマー♡ホリデイ）
- **ステージ属性**: **Vocal特化**（センター属性: Vocal）
- **属性重み**: Vo 600‰ / Da 250‰ / Vi 150‰（合計 1000‰）
- **来場者数**: 16,000人（fan倍率: 来場者配分式）
- **ノーツ内訳**: 総ノーツ 156（**通常ビート 138** / Aスキル 16 / SPスキル 2）
- **全156ビートの照合結果**:
  - $\lambda = 8/140$ を前提に全ビートの乱数を逆算すると、平均乱数 **1000.95‰（+0.095%）**、全ビートが $[950, 1050]$ に 100% 収束し、ゴールデンスコア **17,521,461,739** が1の位まで完全一致。

## 4. 観察されている事実と検討ポイント

1. **適合係数の乖離**:
   - S4（Dance特化）では **$\lambda = 1/20 = 5.000\%$（やる気士docs式）** が実測と極めて綺麗に一致します。
   - 一方、T5（Vocal特化）および S3（Visual特化）では **$\lambda = 8/140 \approx 5.714\%$** で合致しており、もし $1/20$ を適用すると約 $-13\% \sim -15\%$ 過小になります。
   - この2つの係数の比率を計算すると、約 **1.143倍（数値上は $\frac{8/140}{1/20} = \frac{8}{7} \approx 1.142857$）** の差異が見られます。
2. **ノーツ数等分仮説の検証**:
   - 「曲の通常ビート数 $N_{\text{beat}}$ で割っている」という仮説について検証したところ、S3（通常ビート **148**）と S4（通常ビート **149**）はノーツ数が実質同数（1ノーツ差）であるにもかかわらず、実測の適合係数が異なっています。したがって、単純なノーツ数等分モデルではないと考えられます。
3. **モードや共通計算の整合性**:
   - S3 と S4 はどちらも全く同一の「EXタワー（40,000人、fan倍率1.375）」です。
   - スキルノーツ（SP/A）は S4 でも全件 100% 乱数内に合致しているため、デッキステータス計算、バフ計算、コンボ倍率、ファン倍率などの共通処理にはズレが存在せず、差は通常ビートの基本スコア計算（$\text{basic}$）に局所化されています。
4. **フォトスキルのビートスコア上昇%（beat_score）の挙動**:
   - フォトのパッシブスキルに「ビートスコア上昇 +X%」が存在する場合の重複ルールについて：
   - S3 のレーン4にはフォトが2枚（17.5% と 19.3%）装備されています。
     - $\lambda = 8/140$ のもとでは、最大値のみ（$\max(17.5\%, 19.3\%) = 19.3\%$）を適用すると実測ポップ（86.3K）と合致（比率 1.018）し、合算（36.8%）にすると過大になります。
     - 一方、もし $\lambda = 1/20$ のもとでは、合算（36.8%）を適用するとシミュレータ値 85.3K（比率 0.988）となり実測ポップと合致します。
     - 基礎係数の扱いと、フォトスキルの適用ルールが連動している可能性があります。

## 5. 分析・提案の依頼事項

上記の実測データおよび観察事実に基づき、特定の仮説に囚われず客観的・多角的な観点から、真の通常ビートスコア計算モデルを導出してください。

特に以下の点について見解と提案を求めます：

1. **ステージによる適合係数（5.000% vs 5.714%）の違いを生み出している真の要因は何か？**
   - センター属性（Vocal / Visual / Dance）による補正や相性、属性ごとの基礎パラメータの違い
   - マスタの属性重み（$W_{vo}, W_{da}, W_{vi}$）の内部演算処理（正規化、除数、端数処理の順序など）
   - ステータス参照における何らかの補正項や未考慮の定数
   - ゲーム開発（QualiArts）の実装アーキテクチャとして、最も自然で一貫性のある設計はどのようなものか
2. **フォトスキルの「ビートスコア上昇%」の正しい重複仕様（合算 sum か、最大値 max か、あるいは別の枠組みか）**
3. **T5、S3、S4 の実測値（白ノーツ・スキルノーツ双方）を矛盾なく統一的に説明できる「通常ビートスコア計算式」の具体的な数式モデルの提案**
