# 05. Fable v2 Webアプリ（統一モデル提案）の検証報告

> 検証日: 2026-09-05 / 対象: `https://01a06e58-51bd-73aa-bfa7-7537d0c6ad05.arena.site/`
> 検証スクリプト: 同ディレクトリ `verify_fable_v2.mjs`（`node research/23_beat_score_analysis/pack_v2/verification/verify_fable_v2.mjs` で再実行可）

## 0. Fable 提案のサマリ（Webアプリからの抽出）

| 主張 | 内容 |
|---|---|
| ① | 「S4 が 1/20 で合う」は成立していない。S4 白ノーツ合算の期待σは約1.5%だが実測は ±6% のクラスタ構造を持ち、λ 単独では S4 は閉じない |
| ② | 「8/7」は厳密な整数比ではない。実態は「≈57‰ 群 vs ≈50‰ 群・比 1.14±0.02」 |
| ③ | 差は basic の off-attr 項（レーン属性以外のステータス）に局所化できる。S3-L4 2.7% / T5 15-20% / S4 ≈45% |
| ④ | 統一モデル: `basic = ⌊(own + ⌊off×κ/1000⌋)×λ⌋`、κ 既定 1000、λ は 8/140 維持、フォト beat% は **sum** 既定、フォト beat 固定値は平坦加算 |
| 判定手順 | S4 L2（off 8%）のレーン別ポップで λ を、L1/L3 で κ を決定せよ |

## 1. 検証方法

各サンプルの `sim_trace_full.json`（buffSnapshots 込み）+ `sim_skills.json`（deck 実値）から
ビートイベントを own/off に分解し、κ・λ・フォト規則を変えて再計算し、
実測 `measured_data*.json` のビート獲得スコアと照合した（逐次 floor 完全再現、
再現誤差は advantage 等を除き 0.01% 未満）。

再現確認: κ=1000 で S1/S2/S4 のビート合計はトレース値と 0.005% 以内で一致、S3 も L5 優位 ×2.25 を入れて一致。

## 2. 検証結果

### 2.1 主張③④（κ モデル・off-attr 比率）→ **棄却 / 冒頭数値は誤り**

- **S4 の off-attr 比率は ≈45% ではない**: deck 実値 + ライブバフを用いた分解では
  合算オフ比率は 23-34%（Fable は pack v1 由来の未検証値 752,704 を基に 45% と推定したが、
  これは実機 deck 値と一致しない数値。v1 の basicSum は UI 表示 28,628/19,688/610,404 を
  混ぜたもので、deck.json の total_after（145,788/113,459/305,202）と矛盾する）。
- **κ は単一パラメータとしてサンプル間で矛盾する**:
  - S3（70 純白ビート）: κ=1000 で **70/70 が乱数内**・平均乱数 1003.0。κ=900 で 58/70 に悪化。
  - S2（32 純白ビート）: κ=1000 で平均乱数 **1050.4**（全ビート正側・sd 1.6%）。κ を上げる（≈1080）方向でしか直らない。
  - S4: κ≈850 で平均 1.0 になるが sd 6.5% のままで合格率 54/70 が上限。
  - つまり S4 は κ↓、S2 は κ↑ を要求し、**単一 κ では全サンプルを同時に満たせない**。
- Fable の「S4 は κ に最も敏感」という定性評価自体は正しいが、解は存在しない。

### 2.2 主張①（S4 の残差は非ランダム）→ **判定不能（データ汚染）**

- pack_v2 の「S4 67 純白ビート」には、ポップ遮蔽（OCR 欠落）でクリティカルフラグが
  落ちたビートが多数含まれる。measured_data_v2 の pop 取得状況で全 5 レーン可視の
  ビートに限定すると **4 ビートのみ**（b11/15/16/89）が純白として確定し、
  その範囲では平均乱数 970.3・**4/4 が乱数内**で非ランダム性は確認できない。
- b36-44・b89-99 の「クラスタ構造」は遮蔽ビートの混入（クリティカル過小計上）で
  人為的に作られた可能性が高く、既存データから Fable 主張の検証は不可能。
- 判定にはレーン別ポップの再撮影（Fable 判定手順①②と同じ結論）が必要。

### 2.3 主張②（8/7 非整数比）→ **支持**

- T5 乱数逆算では 57‰/57.14‰/57.5‰ は区別不能（我々の既存知見と同一）。
- ただし「λ=50‰ が真」とする方向は S3-L4 の天秤（後述）と現行エンジン係数の下で不要。

### 2.4 S3-L4 の天秤（§3）→ **係数不整合があり、Fable の前提は無効**

Fable は「off 2.7% の L4 で 86.3K を出すのに λ=50‰ では B1 1.635 が必要」と計算したが、
その入力には現行エンジンと異なる係数を使っている:

| 項目 | pack v1/v2・Fable の前提 | 現行エンジンの実装（実測確定済み） |
|---|---|---|
| B2（コンボ） | `1000+2.5×combo`（b8 → 1020‰） | 閾値テーブル（b8 は combo<10 → **1000‰**） |
| fan | 1375‰ 一律 | **1356‰**（引力式・8,000 人×ファンテーブル） |
| basicSum | 752,704（UI 表示値 28,628/19,688 を使用） | **839,415**（deck 実値 145,788/113,459 × ライブバフ 1000‰ + visual 610,404） |
| B1 | 1303（max）/1478（sum） | 同左 |

現行エンジン係数での再計算（S3-L4 b8・実測ポップ 86.3K）:

- **max 規則（B1=1303）: 84,749 → 比率 0.982（乱数内一致）** ← 現行実装
- sum 規則（B1=1478）: 96,130 → 比率 1.114（全乱数域で過大・不合格）
- λ=1/20+sum: 86,200 → 0.999 に見えるが、off 実値を入れると 76,483 → 0.886（不合格）

つまり **「pack v1 と v2 の 1.117 倍矛盾」（Fable §3 の指摘）は、v1/v2 が現行エンジンと
異なる B2・fan・basicSum を仮定したことに由来する見かけの矛盾**であり、
現行エンジンの係数系では max 規則が確定する。Fable の「sum 既定」提案は棄却。

### 2.5 フォト「ビートスコア（固定値）」の発見（新知見）

- S2/S3/S1 の deck.json には `beat_score: fixed`（S2: L2+474/L4+1150/L5+1148+230、
  S3: L2+1300+1148+1150/L3+920、S1: L1+1300/L2+230/L4+639）のフォト項目が存在する。
- **S3 は flat をビートごとに加算すると 70/70 → 69/70・平均 983 に悪化するため、
  flat のビート常時加算は棄却**。これらはフォト P スキルの score_get（発動時 1 回の固定スコア）
  値であり、パッシブ常時加算ではない（S1 の A スコア固定値と同型の発動型）。
- S2 の白ビート +4.5% シフト（32/32 全ビート正側・sd 1.6% = 純粋乱数の大きさ）は
  flat=end 計算で 32/32・平均 1016 に収まるが、S3 との矛盾からこれは数値の偶然一致であり、
  S2 の真の原因は未解明（既知の S2 全体 ×0.973 ギャップと同方向）。

## 3. 結論

1. **現行実装（λ=8/140・フォト beat は max・κ なし）は S3 で 70/70・S4 クリーン 4/4 と
   整合しており、Fable 統一モデル（κ 導入・sum 既定）に乗り換える根拠はない。**
2. Fable の提げた決定実験（S4 レーン別ポップ回帰）自体は正しい指摘であり、
   レーン別ポップ数値を含む撮影仕様の改善（次サンプル）で λ・off-attr バフ適用の有無を
   一意に判定できる。
3. S2 の白ビート系統的 +4.5% シフト（新発見）と、pack の係数不整合（B2 テーブル・fan 引力式・
   basicSum 実値）を pack_v3 に反映すべき。
