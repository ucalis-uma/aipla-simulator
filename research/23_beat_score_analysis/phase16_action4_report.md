## 2. タスク2: トレース `fan` の 0.6〜1.9% 差 = **引力度配分（集目/ステルス）の per-lane 値**

**結論（一行）: 解析トレースの `fan` 欄は「会場の表引き値（= `f(cap/5)`・※最大）」ではなく、
エンジンの引力度モデル `fanFactorPermilByAttraction` の per-lane 分配値である。**
両者は違う量なので一致しないのが正常であり、バグではない。

| サンプル | trace `fan` | 表引き（会場レベル） | 差 |
|---|---|---|---|
| S1 | 1001‰ | 1002‰（= f(20)、cap 100/5） | −0.1% |
| S3 | 1361‰（レーン平均 1360.8） | 1375‰（= f(8000)） | −1.0% |
| S2 | 1554.6‰ | 1564‰（= f(13,206)） | −0.6% |
| T5 | 1590‰ | 1620‰（= f(16,000)） | −1.9% |

### 2-1. 差の出所（集目 lane への再配分）

`src/timeline/buffs.ts:633 fanFactorPermilByAttraction(baseCount, focus, stealth, others)`:

```
自レーン来場数 = round(baseCount × 5 × 自引力度 / Σ全5人の引力度)   ※引力度 = 1000 + 50×集目 − 50×ステルス
fan = 1000 + fanBonusPermilFromCount(自レーン来場数) + focusFanBonusPermil(集目段数)
```

- S3（b62 付近・`tmp_a4_s3_beats_out.txt`）: L3 が集目 10 段 → **L3 = 1568‰** /
  非集目 4 レーンは `round(8000×5×1000/5500) = 7273人` → **1356‰**。
  5 レーン平均 = 1360.8‰（= 報告の 1361‰。
  `research/12_implementation_log.md:486`「非集目 4 レーン ≈1361‰（トレース平均 1360.8 と一致）」、
  `pack_v3/04a_inquiry_prompt_v3_inline.md:63` の「L3 集目の再配分で非集目 4 レーン ≈1361‰」と同じ）。
  b140 付近（集目 7 段）では L3 = 1542‰ / 他 = 1361‰。
- S1: `baseCount = 20`（cap 100/5）で集目/ステルスの配分を受ける → 再配分後の人数が 18〜19人になる
  レーンが **1001‰**、20〜22人のレーンが **1002‰**。`fan.png` のレーン別来場 **19/19/18/22/22**
  はまさにこの再配分の結果であり、trace の 1001 は「18〜19人組のレーンの値」。
- S2（13,206 → 1564）/ T5（16,000 → 1620）も L3 の集目による再配分で非集目レーンが下がり、
  レーン平均が表引きを 0.6〜1.9% 下回る（`pack_v3/01_context_and_coeffs.md:99`）。

### 2-2. 実装への含意（二重補正の防止 = 今回組み込み済み）

- `fan.png` のレーン別来場数は「再配分済み」の実測値なので、レーン別経路では引力度モデルも
  集目/ステルスの加算も**行ってはならない**（行うと配分が二重にかかる）。
  → `types.ts` の `laneFanFactorPermil` コメント・エンジン 2 サイトの優先分岐・`build.ts` の警告に明記。
- 満員会場では表示が一律 `f(cap/5)` なのに対し引力度モデルは 1356/1568 を出す（§1-5）。
  **レーン別 `laneFans` があれば表示値（実測）を直接使い、この既知のズレを回避する**
  （§1-5 の留保＝適用係数の不確かさは §4-3 で継続）。
- なお本プロンプトの「レーン別 fan 実装時の二重補正やズレを防止」の目的は、上の優先順位と
  「`types.ts` のドキュメント」により満たされる（§1-4 のテストが担保）。

### 3-3. 否定できた容疑（S3）

1. **`beatWeightsPermil` の 2000‰ 二重計上なし**: 超過は発動ビート一般ではなく**バナービートのみ**に
   出現し、金額はノート級（39〜55K）。ビート級の二重計上なら全発動ビートで出るはず。
2. **fan が原因ではない**: S3 は全レーン +37.5% 一律（§1-1）なのでレーン別の記録差を作れない。
3. **L2/L4 突出（+9%）との混同なし**: 突出は n=5 の全ビートにわたる系統差で、b63/b71/b141 の gap
   （隠れた 1 本）とは別物。両方を混ぜて `pop合計/バー増分` を語らない（AGENTS.md の層別ルール）。

### 3-4. 副産物: `banner_skill` 欄の使い方（将来の記録方針）

`measured_data_s3_v3.json` は各レーンに `banner_skill`（そのビートでそのレーンに表示されたバナー名）と
`gained_score_pop`（{text, color} / null）を両方持つ。b61 の L4（`banner_skill: "頑固じゃありません！"`・
pop null）や b73 の L3（`banner_skill: "さらけ出す"`・pop null）のように、**バナーがあるのに pop が
読めない**場合は「そのレーンの pop がバナーに隠れた」と読め、gap の金額（88.5K / 64.1K =
当該レーンのノート級）と整合する。将来のレーン別 pop 記録では「バナー付きレーンの pop は欠落する」
