## 1. 結論

**スコアボーナス（ファンボーナス）は各レーンの「来場ファン数」で個別に決まる。**（※満員時は例外: 冒頭の訂正注記）
`サンプル2/fan.png` のレーン別表示 % が、マスタ表を**そのレーンの来場数で引いた値と 5/5 で完全一致**した。

| レーン | fan.png 来場数 | 表示スコアボーナス | 表引き `advantagePermil` | 一致 |
|---|---|---|---|---|
| L1 | 11,996 | +53.9% | 1539‰ → +53.9% | ✅ |
| L2 | 13,543 | +57.0% | 1570‰ → +57.0% | ✅ |
| L3 | 13,741 | +57.4% | 1574‰ → +57.4% | ✅ |
| L4 | 13,255 | +56.5% | 1565‰ → +56.5% | ✅ |
| L5 | 13,496 | +56.9% | 1569‰ → +56.9% | ✅ |

- 来場数の合計 11,996+13,543+13,741+13,255+13,496 = **66,031** = 見出し「来場ファン数 66,031人」✅
- **平均 = 13,206.2** = `サンプル2/deck.json` の `audience: 13206` ✅（＝現行の入力規則は「レーン平均」で正しい）

## 2. 「※最大 +X%」の正体 = `表引き(capacity ÷ 5)`

fan.png の注記「スコアボーナス ※最大+58.0%」は**その会場で取りうる最大値**で、
`audience_advantage.json[capacity/5]` と一致する（3サンプルすべてで確認）:

| サンプル | 会場 (`cap`) | `cap/5` | 表引き | 注記の表示 |
|---|---|---|---|---|
| S2 | `qt-tower-680` (70,000) | 14,000 | 1580‰ → +58.0% | **※最大+58.0%** ✅ |
| S1 | `qt-area-1-001` (100) | 20 | 1002‰ → +0.2% | **※最大+0.2%** ✅ |
| T5 | (80,000) | 16,000 | 1620‰ → +62.0% | （`research/09 §4.1` が見た **+62.0%**）✅ |

→ **`research/09_buffs_criticals.md §4.1` の「+62.0% が5列すべて同一 → レーン平均（=cap/5）の可能性」は誤り**。
あれは注記行（※最大）の値であり、`§4.2` が疑っていた通り OCR（照合 0.77-0.94・全列同一パターン）の産物。
T5 のレーン別来場（17,070 / 16,285 / 15,546 / 15,540 / 15,559）を表で引くと
**+64.1 / +62.5 / +61.0 / +61.0 / +61.1%** で、レーン別の値が実際には異なることと整合する。

## 3. 計算機側の現状との差分

- `src/sim/build.ts:728` → `fanFactorPermil = fanBonusPermil(options.audience, data.audienceAdvantage)`
  ＝**単一の audience を全レーンへ適用**（レーン平均による代表値）。レーン別の来場数入力には未対応。
- S2 でレーン別値へ差し替えた場合の係数比（`f(レーン) / f(平均)`）:

| L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|
| 0.98402 | 1.00384 | 1.00639 | 1.00064 | 1.00320 |

→ **合計スコアにはほぼ効かない**（平均 1.0002・レーン平均は代表値として優秀）が、
**レーン間の相対差は最大 2.2%（L1 を +1.6% 過大／L3 を −0.6% 過小）**。
S2 の `deck.json` には `lane_fans` が無く（レーン別来場が未記録）現状はレーン平均しか使えない。
