## 3. 残る主候補（Action11 で裁く順）

1. **ライブボーナスが実機で発動していたか**（sim の不発が正しいのか）。
   実測側の材料: `サンプル2/live_bonus.png` の現物（バフ欄・発動表示）、45 ビート窓に相当する
   実測 pop の段差、`stat_value` の段差。**live_bonus.png は「そのステージのライボ定義の表示」で
   あって発動の証拠ではない**点に注意（`stage.live_bonus_check` の文言は「定義と表示が一致」）。
   もし実機で発動していたなら **score_up 10 段階 × 45 ビート × vocal_high_2** が丸ごと欠落している。
   → L3 の b〜100 の段差（−10%）と窓が合うかを先に見る（合えば第一候補が本命）。
2. **ノーツ素点のレーン依存係数**。S1 は同じ経路で +0.25% に収まっているので、
   **S1・S3 でも同じ「act なしセルの sim/pop 比」をレーン別に出して 1.00 になるか**を確認するのが最短路
   （S2 固有の要因 = 空席ステージ／SP 枠／属性 dance の枠／`blue_dots`・`pop_class` の違い 等を切り分ける）。
   モデル側の候補: ノーツ素点の λ がレーン属性・ノーツ種別（多/SP/少）・属性重み（S2 は vocal 600 /
   dance 250 / visual 150）に依存している可能性。
3. **L3 の b〜100 の −10% 段差**。`sk-ktn-05-fest-02-2`（暗闇を照らす月）= `effect_extension`（延長）を
   持つので、延長の適用ビート・対象・重複規則のいずれかがずれていないか。

## 6. 実測の「効果表示（段数）」との突合（2026-10-02 追記・質問「スキルは各レーン段階数まで一致しているか」への回答）

方法: 実測 `timeline[].lanes[].effects`（`{name, stage}` の配列）と、sim の `beats[].buffSnapshots`
（レーン別の実効段数スナップショット・全キー）をセル単位で突合した
（[`phase16_action11_buff_stage_compare.ts`](phase16_action11_buff_stage_compare.ts)。
表示タイミングの差を考慮し「同ビートまたは次ビート」で一致と判定）。

**結果: 効果表示のある 543 セル中 432 セル（80%）が全項目一致。** バフ種別ごと（同ビート一致）:

| 実測の表示名 | 実測セル数 | 一致 | 備考 |
|---|---:|---:|---|
| 集目 | 115 | **115（100%）** | |
| スキル成功率上昇 | 157 | 155（99%） | |
| Aスキルスコア上昇 | 121 | 118（98%） | |
| クリティカル率上昇 | 162 | 159（98%） | |
| スコア上昇 | 161 | 157（98%） | 例: b41×L3 実測3 vs sim0 |
| ビジュアル上昇 | 422 | 407（96%） | |
| クリティカル係数上昇 | 238 | 112（47%） | **突合方法の問題を含む**（下記） |
| **SPスキルスコア上昇** | 78 | **4（5%）** | **実測6段階 / sim は全ビート 0**（下記） |

1. **SPスキルスコア上昇の欠落（新しい具体的な切り口）**
   実測 b90 L2 で P「胸いっぱいの勇気」（`sk-skr-05-fest-00-3` Lv2・cost 262・CT70・
   「誰かがSPスキル発動前／対象1人に6段階SPスキルスコア上昇」）が発動し、その表示が **b90〜b167 に残る**。
   sim 側は**発動自体はしている**（発動記録の食い違いは「実測のみ b32 L4 SP FAIL（スキル未習得）」の 1 件だけで、
   b90 L2 は一致）にもかかわらず、`sp_skill_score_up` が **全ビート 0**＝**効果の付与（対象解決）が成立していない疑い**。
   → タスク2 の修正候補として独立に検証する（`someone_before_special` の `triggerLanes` を使った効果適用の対象解決）。
2. **クリティカル係数上昇の 47% は突合方法の産物を含む**
   実測は「クリティカル係数上昇 8段階」と「**クリティカル係数上昇超化** 10段階」を**別プールとして同時表示**する
   （b14/b15/b41/b90 で確認）が、sim は `critical_coeff_up` の**1 キー**しか持たない。本スクリプトは両方を同じキーへ
   寄せているため一致率が下がる。**「超化」が別の段数上限・別の 1 段あたり値を持つのか**は未検証（要確認）。

**A2 の既存出力（`tools/analyze_beat_score_models.ts` → `phase16_action9c_models_S1S2S3_after_F3.txt` 141〜177 行）
が同じ突合をレーン別に持っており、こちらが決定的**:

| レーン | 能力値（実測 vs sim） | 効果段数の一致 | 白ノーツの比（実測/sim） |
|---|---|---|---|
| L1 vocal | 95,322 / 95,327 | **一致 100 / 不一致 0** | 1.0065 |
| L2 vocal | 完全一致 128/128 | （不一致なし） | 1.0613 |
| L3 vocal | 完全一致 39/39 | **一致 20 / 不一致 19** | 1.0276 |
| **L4 dance** | 完全一致 132/132 | **一致 96 / 不一致 0** | **1.2146** |
| L5 vocal | 完全一致 128/128 | **一致 92 / 不一致 0** | 1.1091 |

- L3 の不一致 19 件の内訳: `SPスキルスコア上昇（実測6/sim0）×16`・`クリティカル係数上昇超化（実測10/sim?）×15`・
  `クリティカル係数上昇（実測8/sim13）×4`。
- **L4 は段数が完全一致（不一致 0）なのに比が 1.21**・L5 も 1.11・L2 も 1.06
  → **原因はバフ段数ではなく「レーン依存の素点係数」**（＝§3-2 の本命候補）。段数説は L2/L4/L5 では否定される。
- 同出力の結論: 最良仮説（D+fixed後）でもレーン横断で **系統 +1.98% のオフセットが残留**（レーン非依存の不足
  ＝ライボ等の % 項か λ の可能性）。
