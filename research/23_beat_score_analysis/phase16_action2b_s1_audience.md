実行: 2026-09-30 ／ 対象: S1, S3, T5, S2 ／ 担当: cline（Phase 16 アクション2 の継続）
ツール: `tools/analyze_beat_score_models.ts` ／ 生ログ: `phase16_action2c_all.txt`（補正後）・`phase16_action2_raw_inputs.txt`（補正前の再現）

## 1. 結論（一行）

**サンプル1 の `deck.json audience = 71000` は来場ファン数ではなく、ステージ `qt-area-1-001` の
目標スコア `clear = 71000`（左上表示「18,780,790/71,000」）の誤読だった。**
これにより fan がテーブル上限 **2000‰** に化けて全スコアが約 2.27 倍 over-produce していた（+127.36%）。
会場キャパ `cap = 100` から `src/cli/simulate.ts` と同一規則で導出した個人来場数 **20 人 → fan 1002‰**
に補正すると、S1 総スコアは **116,829,040 / 実測 116,537,513 = +0.25%** に収束した。
**通常ビート計算式（λ=8/140）・フォト規則・クリティカル・バフはいずれも無変更でよい。**

（`basic`・能力値表示突合は 5 レーン完全一致・効果段数一致 203/203 → シミュレーション状態は正しい）

## 3. 対症ではなく一般規則として実装した

`tools/analyze_beat_score_models.ts` に `resolveAudience(tag, declared, stageId)` を追加:

| 条件 | 挙動 |
|---|---|
| 宣言値 == ステージの `clear` | **補正**（目標スコアの誤読と判定）→ `floor(cap/5)`、理由をレポートに `★` 出力 |
| 宣言値 > 会場キャパ `cap` | **補正**（観客数が会場容量を超える物理的矛盾）→ 同上 |
| 宣言値 > `cap/5` | **警告のみ**（宣言値を採用・fan.png 再確認を促す） |
| それ以外 | 無変更 |

- `cap/5` はゲーム側の個人来場数上限（`src/cli/simulate.ts:283-295` の導出規則）。
  **S3 の fan.png 実測 8,000 が cap 40,000/5 と完全一致**、S2 13,206 ≦ 70,000/5=14,000 で上限直下。
  つまり cap/5 が実際の上限であることを実測が裏付けている
- ⚠️ **訂正（同セッション後続の `phase16_action3_fan_per_lane.md`）**: 以前本節に書いた
  「T5 のボーナス表示 +62.0% が5レーン同一 → ボーナスはレーン平均（=cap/5）で算定される」という
  独立証拠は**誤り**。+62.0% は fan.png の**注記行「※最大」の値**（= `f(capacity/5)`）で、
  レーン別表示は各レーンの来場数で表を引いた値と **S2 で 5/5 完全一致**した
  （L1 11,996→+53.9% / L2 13,543→+57.0% / L3 13,741→+57.4% / L4 13,255→+56.5% / L5 13,496→+56.9%）。
  → **ボーナスの算定はレーン別**。`cap/5` は「入力 `audience` の上限（＝レーン平均の取りうる上限）」
  であり、`f(cap/5)` は「その会場で取りうる最大ボーナス」の意味。S1 は全レーン 18〜22人で
  表引き値がすべて +0.2% に収まるため、レーン別でもレーン平均でも同じ表示になる（判別不能）
- S3/S2/S1 の全宣言値を同じ関数に通しており、**非該当＝その値が正当であることの検証**になっている
- **`サンプル1/deck.json` は実測入力なので未変更**（変更したのは解析側の入力解決のみ）
- `--raw-inputs` フラグで補正前を再現可能（`phase16_action2_raw_inputs.txt` = 本報告の +127.36% の証拠）

副次修正（同じファイル）:

### 8-4. 副産物の教訓（工具運用）

- PowerShell の `Select-String`・コンソール出力はコードページ都合で**日本語が化けて見える**
  （ファイル自体は無傷）。**文字化けの有無はコンソール目視や安直な正規表現では判定できない**
  （文字クラスに常用漢字が紛れ込むと正常文が大量ヒットする）。判定は `node -e` で UTF-8 として読み、
  Shift-JIS 誤読で生じる文字列の出現数を数えて行う（本セッションでも誤判定で正常なレポートを
  1 件削除した。`phase16_action2_stdout.txt` は `phase16_action2_raw_inputs.txt`（補正前再現）と
  `phase16_action2c_all.txt`（補正後）に置き換え済み）
- `--quiet` は「コンソール出力の抑制」だけを意味する（レポートは必ず書く）。レポート上書き事故
  （`phase16_action1_stdout.txt` に A2 実行内容が混入）は `.bak` から復元済み。教訓を §3 の副次修正に記録
