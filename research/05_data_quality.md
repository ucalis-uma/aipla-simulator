## 3. 発見した異常値・ノイズの完全リスト

### A. スタミナ異常値（OCR由来・確定）
- **Lane 2, beat 97〜101 の 5 ビートで `current_stamina = 60,911`（max 15,609 を超過）**。周辺の差分は +60,000 / −53,488 という非現実値で、表示へのポップアップ重畳等による読み取り誤り。真値は前後（beat 96 = 911、beat 102 = 7,423）から 911 前後かそれ以下の可能性が高いが復元不能。
- beat 102 の 7,423 も連続性から疑わしい（911 から回復スキルなしで +6,512 は説明不能）。**Lane 2 の beat 86〜120 は要再読取**。

### B. スタミナ null（UI 遮蔽・読取失敗）
- Lane 1: beat 101〜156 の 56 ビート
- Lane 2: beat 47〜59 の 13 ビート
- Lane 4: beat 51〜156 の 106 ビート
- Lane 3 / Lane 5: null なし
- 緩和策: `skill_activations[].stamina`（"発動後スタミナ"）が Lane 1 = 12 ビート、Lane 2 = 21、Lane 3 = 11、Lane 4 = 15、Lane 5 = 14 の時点で別ソースとして存在し、null 区間の部分補完が可能。

### C. `skill_cts`（残 CT）は実質使用不可 × 判定
- 観測値が **0 / 1 / 6 の 3 種のみ**。CT50 のスキルが「1」「6」と記録されるなど発動事実と無相関（例: Lane 3 slot3 が beat 12〜15 で「6」、ただし Lane 3 の発動は beat 2 と 69 の間に存在しない）。
- 結論: **OCR が CT 表示を安定して読めていない。ゴールデン照合のアサーション対象から除外**し、CT の検証は「発動間隔 ≥ CT」則（§2 最終行）と CT 短縮事象の差分推定で代替する。

### D. effects の同種バフ重複（表示スクロールのマージ誤差）
- 同一レーン同一ビートに同一名の effect が 2〜3 個並ぶ事例 **460 件、すべて Lane 3**（432枚のスクロール画像をマージした経緯による）。Lane 1/2/4/5 は重複ゼロ。
- 例: beat 1 Lane 3 `focus` が 6段階と3段階の 2 行。

### E. `combo_continue` に段階数が付与された混入
- 「コンボ継続」は段階なし効果だが、**stage = 7〜9 が付いた行が 55 件（すべて Lane 3）**。隣接アイコンの段階数の取り込みミス。Lane 1/2/4/5 では stage = null で正常。

### F. beat 1 で「コンボ 1 なのに獲得スコア 0」
- `combo=1, cumulative=0, gained=0`。beat 2 で +514,083。初回ノーツのスコアポップが「LIVE START」表示に隁れて未読取、または累積カウンタ更新前のフレーム截取の可能性。**真の初手スコアは本データからは検証不能**（Δビート帰属の不確実性、§4-I 参照）。

### G. beat 156 でコンボが増加しない
- beat 155 で combo=155（= リザルト COMBO）に到達後、beat 156 はスコア +1,708,961,981 を記録するがコンボ据え置き。最終フレームの更新前截取の可能性。**境界ビート（0 と 156）はコンボ・スコア帰属のアサーションを緩めるべき**。

### H. リザルト判定内訳が整数カウントと逆算不能
- CRITICAL 22.3% / HIT 94.4% / MISS 0。ノート数 N（155〜157 候補）のいずれを取っても、両者が同時に整数カウントに一致しない。
  - N=155: 22.3% → 34.57 枚 / 94.4% → 146.3 枚
  - N=157: 35/157 = 22.29% は一致するが、HIT は 148/157 = 94.27% で不一致
- 少なくとも片方は OCR 誤差または分母の異なる指標。**判定内訳は低信頼**（クリティカル枚数は 33〜35 枚のレンジでのみ拘束）。

### I. レーン別スコアポップアップは「表示丸め + 反映タイミングずれ」を含む近似
- ポップアップ数値は `gained_score` も常に表示値の切り捨て（'+39.3K'→39300 等。10^k の整数倍でない例は 0 件）で、**有効数字 3〜4 桁**。K: ±100 / M: ±10万 / G: ±1億 の量子化誤差。
- カバレッジ 674/785 セル（85.9%）。レーン別ポップアップ合計と results レーン別獲得スコアの差: L1 −646,493(−3.0%) / L2 −1,175,862(−2.2%) / L3 −69,231,531(−0.4%) / L4 −802,259(−3.4%) / L5 −856,479(−2.6%)。
- **ビート単位の合計とも一致しない**（全 156 ビートで「ポップアップ合計 = beat_gained_score」は 0 件。±5% 以内 136、乖離 18、ポップなし 2）。特に A スキルスコアは発動ビートにポップが出ても累積への反映が翌ビートの例がある（beat 2 発動 +24.5M ポップ → beat 3 に +25.58M 反映。beat 47→48 も同様）。一方最終 A（beat 156）は同ビート反映。**A スキルスコアの帰属ビートは ±1 の不確実性あり（仕様未確定領域）**。

### J. Lane 3 `stat_value` の平台上限
- 変化点は beat 1, 2, 3, 38, 50, 51, 60, 68 の 8 点のみ。beat 68 以降 156 まで **2,348,336 で固定**。これは `floor(626,223 × 3.75)` と完全に一致し、バフ段階の揺れ（5〜20段階）が値に反映されていない。**表示上限 or 乗算式+切り捨ての強い手がかり**だが、真の途中値が隠れている可能性があるため中間ビートの照合は非推奨。

### K. その他の小規模ノイズ
- effects の `stage=null` は 2,551 行中 571 行。うち大半は `combo_continue`（段階なし効果）で正常。`score_up` 2 行・`stamina_cost_down` 2 行の null は読取漏れの疑い。
- verification_data 側に `unreadable` フォト（Lane 1 の 1 枚等、skill 欄 "None"）があり、フォト 4 枚目の同一性は一部未確定。
- beat 156 で Lane 1/2/4/5 の effects が 1 個（コンボ継続のみ）に減少。ライブ終了時の表示クリアで、残バフ照合の境界外扱いが妥当。

### L. 示唆的観測（異常ではないが式検証の重要手がかり）
- **スコア乱数の存在を示唆**: Lane 1 の beat 3〜10 はバフ・ステータス一定（コンボのみ増加）なのに、ポップが +36.2K〜+39.4K と ±4% で増減（コンボボーナスは単調増加のはずで下振れを説明できない）。同一状態でのスコア乱数 ±数% の実験的証拠。
- **CT 短縮の実測**: Lane 4 の A「ドリームウエディング」（beat 106、隣接 CT 減少）の後、Lane 3 P スキルの発動間隔が 50 → 35 に短縮、Lane 5「さらけ出す」(CT60) も 60→106 の 46 で発火。
- **発動条件の実測**: Lane 1 フォト「クリティカルスキル（80コンボ以上・ライブ中1回のみ）」は combo=81 の beat 81 に 1 回のみ発火。条件一致。
- **SP FAIL の実測**: beat 49 Lane 4（SP 未所持）→ `gained=0`、**コンボは継続（48→49）**、スタミナ無消費（13519 のまま）。スキル失敗時コンボ仕様の一次証拠。
- Lane 3 の効果時間表記（例: [44ビート]）と effects 消滅ビートの突合により、効果時間の off-by-one（発動ビートを含む/含まない）を検証できる素データがある。

## 4. 信頼性マップ（どこまで 1 の位で信頼でき、どこからが近似か）

| データ | 信頼度 | ゴールデン照合での扱い |
|---|---|---|
| `cumulative_score`（全157点） | ◎ 1の位まで確定 | **全ビート完全一致**を要求してよい（内部差分・最終値・レーン合計の三重整合済み） |
| `beat_gained_score`（差分値として） | ◎ 差分としては 1 の位まで確定 | 完全一致。ただし「どのノーツ/スキルが稼いだか」のビート帰属は A スキルスコアで ±1 の不確実性（§3-I/F/G） |
| `results.total_score` / レーン別獲得スコア（5個） | ◎ 確定 | 完全一致の最終アンカー |
| `skill_activations` 82 件（順序・ビート・レーン・種別・発動後スタミナ） | ◎ 確定 | 完全一致（発動後スタミナは null 区間の補完用データとしても 1 の位照合可） |
| `combo` | ○ 確定（境界除く） | beat 1〜155 は完全一致。beat 0/156 は「非減少」のみ要求 |
| beat 0 の `stat_value` / `max_stamina` | ◎ 確定 | verification_data と突合済み。完全一致 |
| `stat_value` 推移（Lane 3 の 8 変化点） | ○ 中〜高 | 変化点ビートの完全一致＋平台上限値 `2,348,336` の一致を要求。中間ビートの個別値は非推奨 |
| `current_stamina` | ○（Lane 3, 5）／△（Lane 1, 2）／✕（Lane 4 は 51 以降 null） | null でない区間のみ完全一致。**Lane 2 beat 86〜120 は既知ノイズとして除外**（§3-A）。Lane 4 は発動ログ 15 点での部分照合 |
| `effects` | ○ Lane 1/2/4/5 ／△ Lane 3 | Lane 1/2/4/5 は id+段階の完全一致を要求可。Lane 3 は「含まれるべきバフの部分集合一致（multiset 非厳密）」に留める（重複 460 件・混入 55 件のため） |
| レーン別 `gained_score`（ポップアップ） | △ 近似（有効数字 3〜4 桁・カバレッジ 86%・±1ビートずれ） | アサーション禁止。レーン別集計の **±4% レンジ照合**とトレンド（増減パターン）の Sanity チェックのみ |
| `skill_cts` | ✕ 使用不可 | 一切アサートしない。CT 検証は発動間隔則で代替 |
| 判定内訳（CRITICAL 22.3% / HIT 94.4%） | △ 低信頼 | レンジ照合のみ（クリティカル 33〜35 枚、HIT 146〜148 枚）。式確定後の再検証課題 |
| verification_data の基礎ステータス・CT・消費・交流Lv | ◎（一次画面転記） | ゴールデン入力として使用（unreadable フォト 1 枚のみ要注意） |

## 6. 推奨フォローアップ（データ再抽出・追加実測）

1. **Lane 2 stamina の再読取**（beat 86〜120 の元画像 35 枚）— ゴールデンのスタミナ照合範囲を広げられる。
2. **Lane 4 stamina の補完読取**（beat 51 以降、ポップが重ならないフレームがあれば）。
3. **CT 表示の再アプローチ**（skill_cts は放棄し、発動間隔則ベースに。あるいは CT ゲージの別領域クロップで再 OCR）。
4. **リザルト画面の再読取**（CRITICAL/HIT の片方が誤読の可能性）。
5. **第 2 ライブの実測**（クリティカル発生ビートが分かる範囲で。スコア乱数の偏り推定と、判定内訳逆算の検証に直結）。少なくとも別編成・別曲 1 本があると、バフ上限・丸め位置の式が交差検証できる。
6. Lane 3 effects のスクロールマージについて、`scratch/lane3_beat_map.json` のマッピングを用いた再検証（重複 460 件の縮減）。
